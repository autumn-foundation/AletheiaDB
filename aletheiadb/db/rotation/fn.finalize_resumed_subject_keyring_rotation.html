Expand description

Finalize a startup- or live-resumed crypto-shred SUBJECT-KEYRING re-wrap (Slice 5), completing the re-wrap pass and clearing the rotation ledger.

The subject keyring is the LAST layer to settle in a full-MEK rotation: it runs after index / WAL / cold have all been re-keyed (each of those finalize passes now defers the ledger clear while layer.subject_keyring is Pending), so this function performs the final ledger clear. It is idempotent and resumable:

  1. re-derive the OLD subject-wrap cipher from the CURRENT (live) MEK — during a resume-under-old-key the encryption config still points at the old key — and the NEW subject-wrap cipher from the ledger’s recorded new source;
  2. run [CryptoShredState::rewrap_keyring], which skips erased subjects and entries already at the target version, so a crash mid-pass resumes with no double-wrap and no error;
  3. mark layer.subject_keyring=complete and clear the ledger.

A no-op (Ok(())) when no ledger is present, the layer is not Pending, or the direction is enable — so db::config and the live resume can call it unconditionally.

§Crash caveat: keep the OLD MEK available until this completes

Identical in spirit to the cold layer’s contract (finalize_resumed_cold_rotation): while layer.subject_keyring is Pending, the OLD MEK must remain the live encryption source so the old subject-wrap cipher can unwrap the still-old-generation per-subject DEKs during this resumed pass. If the operator instead reopens under the NEW key alone while the re-wrap crashed mid-pass, the surviving old-generation wrapped DEKs can no longer be unwrapped — a loud AEAD authentication failure, so the pass returns Err rather than silently corrupting the keyring. Recovery is lossless: reopen once under the OLD key so this resume completes (re-wrapping every entry at the new generation and clearing the ledger), after which the new key alone unwraps everything. The fault is availability-only, never data loss.

§Errors

Returns an error if the old or new MEK cannot be sourced, or the re-wrap pass fails (a genuine wrong/absent key surfaces loudly; the ledger is left Pending for a later resume).
