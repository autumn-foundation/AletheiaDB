## 1. 👤 User Story

> **As a** Knowledge Graph Architect,
> **I want to** automatically segment the graph into semantic regions based on vector similarity,
> **So that** I can visualize the "landscape" of the data and perform coarse-grained routing (Cluster-based Retrieval) without manual categorization.

## 2. 🧐 The "So What?" (Business Value)

**The Problem:**
Large graphs often become "hairballs"—visually and structurally unintelligible. While Vector Search allows finding "nearest neighbors," it does not provide a high-level map of the data's topology. Users cannot ask "What are the main topics in this dataset?" without expensive external processing.

**The Solution:**
"The Cartographer" reifies the latent vector space into the explicit graph structure. By clustering nodes and creating explicit `Region` nodes, we turn implicit mathematical similarity into explicit, traversable relationships.

**ROI:**
-   **Automated Taxonomy:** Automatically discover categories (e.g., "Finance", "Healthcare") in unstructured data.
-   **Optimized Retrieval:** Enables "Two-Stage Retrieval" (Find closest Region -> Search only nodes in that Region), drastically reducing search space for huge datasets.
-   **Observability:** Allows business users to "see" what kind of data resides in the system by inspecting Region centroids.

## 3. ✅ Acceptance Criteria

### Functional Requirements
1.  **Analysis API**:
    -   Must accept a `property_name` (holding the vectors) and `k` (number of clusters).
    -   Must execute K-Means clustering on the selected vectors.
    -   Must handle disconnected components (clustering is based on vectors, not edges).

2.  **Graph Reification**:
    -   Must create new nodes with label `Region`.
    -   Must store the cluster's center vector as `centroid` property on the `Region` node.
    -   Must link original nodes to their assigned `Region` via `LOCATED_IN` edges.

3.  **Idempotency & Lifecycle**:
    -   **Gap**: Current implementation is append-only.
    -   **Requirement**: A `reify` operation should ideally tag the run (e.g., `run_id`) or allow clearing previous regions generated by the same configuration to prevent "Region explosion."

4.  **Performance**:
    -   Must handle 100,000 vectors in < 10 seconds (Batch operation).
    -   Must not block read transactions on the rest of the graph during the calculation phase (write lock only needed during reification).

### Non-Functional Requirements
-   **Deterministic Initialization**: To ensure reproducibility, K-Means initialization should be deterministic (e.g., seeded or fixed interval selection), not random.
-   **Safety**: Must handle nodes with missing vector properties gracefully (skip them).

## 4. 🚫 Out of Scope (Phase 1)

-   **Dynamic Clustering**: Updating clusters in real-time as nodes are added. (This is a Batch job).
-   **Hierarchical Clustering**: Creating Regions within Regions.
-   **Automatic K**: The user must specify `k`. (Elbow method estimation is Phase 2).
-   **Alternative Algorithms**: DBSCAN or HDBSCAN (We stick to K-Means for speed/simplicity).
