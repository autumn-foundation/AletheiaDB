1//! Vector utilities for AletheiaDB.
2//!
3//! This module provides types and functions for working with dense vectors
4//! (embeddings) used in semantic search and similarity operations.
5//!
6//! # Overview
7//!
8//! AletheiaDB supports storing vectors as property values on nodes via
9//! [`crate::core::PropertyValue::Vector`]. This module provides the utilities needed
10//! to work with those vectors effectively:
11//!
12//! - **Type definitions**: [`VectorDimension`] for expressing vector sizes
13//! - **Similarity functions**: [`cosine_similarity`], [`cosine_similarity_normalized`]
14//! - **Distance functions**: [`euclidean_distance`], [`squared_euclidean_distance`]
15//! - **Inner product**: [`dot_product`] for pre-normalized vectors or projections
16//! - **Normalization**: [`magnitude`], [`squared_magnitude`], [`normalize`], [`normalize_in_place`], [`is_normalized`]
17//! - **Validation**: [`validate_vector`], [`check_dimensions_match`] for NaN/Inf detection and dimension checking
18//!
19//! # Usage
20//!
21//! ```rust
22//! use aletheiadb::core::vector::VectorDimension;
23//! use aletheiadb::core::PropertyValue;
24//!
25//! // Create a vector property
26//! let embedding: Vec<f32> = vec![0.1, 0.2, 0.3, 0.4];
27//! let dim = VectorDimension::new(embedding.len());
28//! let prop = PropertyValue::vector(embedding);
29//!
30//! // Access the vector
31//! if let Some(vec) = prop.as_vector() {
32//!     assert_eq!(vec.len(), dim.as_usize());
33//! }
34//! ```
35//!
36//! # Design Notes
37//!
38//! Vectors in AletheiaDB are stored as `Arc<[f32]>` within [`crate::core::PropertyValue::Vector`].
39//! This design enables:
40//!
41//! - **Efficient cloning**: Multiple versions can share the same vector data
42//! - **Memory efficiency**: f32 provides good precision with half the memory of f64
43//! - **Temporal compatibility**: Unchanged vectors across versions share storage
44//!
45//! For similarity computations, vectors should typically be L2-normalized to enable
46//! fast cosine similarity via dot product.
47//!
48//! # Type Safety
49//!
50//! [`VectorDimension`] is implemented as a newtype struct rather than a type alias.
51//! This provides stronger type safety by preventing accidental interchange with
52//! other `usize` values (e.g., byte counts, array indices).
53//!
54//! # Implemented Functions
55//!
56//! - **[`cosine_similarity`]**: Measures angle between vectors, range `[-1, 1]`
57//! - **[`cosine_similarity_normalized`]**: Optimized for pre-normalized (unit) vectors
58//! - **[`euclidean_distance`]**: L2 distance between vectors
59//! - **[`squared_euclidean_distance`]**: Squared L2 distance (faster for comparisons)
60//! - **[`dot_product`]**: Inner product, useful for pre-normalized vectors
61//! - **[`magnitude`]**: L2 norm of a vector
62//! - **[`squared_magnitude`]**: Squared L2 norm (faster for comparisons)
63//! - **[`normalize`]**: Returns new unit vector with magnitude 1.0
64//! - **[`normalize_in_place`]**: Normalizes vector in place
65//! - **[`is_normalized`]**: Checks if vector has unit magnitude
66//!
67//! All functions use SIMD acceleration via the `simsimd` crate when the
68//! `simsimd` feature is enabled (x86 AVX2/AVX-512 and ARM NEON/SVE, selected at
69//! runtime), and a portable scalar fallback otherwise (Issue #426).
70//!
71//! # Future Additions
72//!
73//! This module will be expanded to include:
74//!
75//! - Manhattan distance
76//! - Dimension validation helpers
77//! - Sparse vector support
78//!
79//! See `docs/VECTOR_SEARCH_DESIGN.md` for the complete design.
