1//! Plaintext → encrypted-at-rest migration engine (Issue #3616 PR3).
2//!
3//! This is the engine behind `aletheia encryption enable`: it takes a database
4//! that was created **plaintext** and migrates the WAL through the cipher, then
5//! flips the durable [`encryption.state`](crate::db::encryption_state) authority
6//! so the *next* [`open()`](crate::AletheiaDB::open) comes up encrypted.
7//!
8//! It composes the two foundations that already landed:
9//! * **PR1 (#3657)** — the durable [`encryption.state`] authority the migration
10//!   flips (authority WINS over the operator's TOML/env config).
11//! * **PR2 (#3669)** — the WAL runtime
12//!   [`install_wal_keyring`](crate::storage::wal::concurrent_system::ConcurrentWalSystem::install_wal_keyring)
13//!   seam that flips a live plaintext WAL to encrypted (`None → Some`) crash-consistently.
14//!
15//! # Migration ordering (the crux — do not reorder)
16//!
17//! 1. **Quiesce the background index-persistence thread FIRST** (stop + join).
18//!    While a live keyring is still `None`, a background persist could overwrite
19//!    a freshly-encrypted file with plaintext. The stop happens while the whole
20//!    database is still plaintext, so the worker's shutdown final-persist is a
21//!    safe plaintext write.
22//! 2. **Migrate every in-scope at-rest layer**, recording progress as a per-field
23//!    [`LayerStatus`](crate::db::rotation) in a durable `direction=enable`
24//!    rotation ledger so a crash mid-migration resumes idempotently:
25//!    * **WAL** — install the DEK keyring via the PR2 seam (which seals the
26//!      plaintext segment and force-rolls to a fresh encrypted v16 segment).
27//!    * **Index + checkpoint** — a plaintext → `AEIX` wrap pass rewrites every
28//!      bare index file under the index DEK (checkpoints ride the index DEK and
29//!      format, so they are covered by the same pass).
30//!    * **Cold** — a bare → `ACV1` wrap-only pass rewrites every stored cold value
31//!      wrapped under the cold DEK (only when a cold tier is present).
32//! 3. **Flip the [`encryption.state`] authority to `enabled` BEFORE clearing the
33//!    ledger.** This binding order closes the crash gap: were the ledger cleared
34//!    first and a crash struck before the authority flip, the next `open()` would
35//!    read the unchanged plaintext config over now-encrypted bytes and mis-read
36//!    (undecodable) ciphertext as plaintext. With the authority flipped first, a
37//!    crash between the two steps leaves a still-present ledger that
38//!    [`resume_pending_enable`] reconciles on the next `open()`.
39//! 4. **Clear the ledger.**
40//!
41//! # In scope vs deferred
42//!
43//! In scope: **WAL**, **index**, **checkpoint**, and **cold**. Each layer's
44//! migration is byte-preserving and reader-compatible on reopen (the index reader
45//! header-sniffs `AEIX`; the cold reader dispatches on the `ACV1` wrapper).
46//!
47//! Deferred (NOT migrated by v1): `.albk` backups, `snapshots.json`, auth
48//! `keys.json`, `schema_constraints.dat`.
49//!
50//! # Security caveats (defense-in-depth, documented)
51//!
52//! * **In-place overwrite does not shred freed plaintext blocks.** The index wrap
53//!   writes ciphertext to a temp file and `rename`s it over the plaintext file, and
54//!   the cold wrap `insert`s over the bare redb value; in both cases the OLD
55//!   plaintext data blocks are merely *freed*, not zeroed (redb is copy-on-write and
56//!   is not compacted here). Enable protects against the "logical FS read / stolen
57//!   disk image" threat model, but it is NOT a plaintext-shredding operation:
58//!   forensic recovery of freed blocks can still resurrect pre-enable plaintext. A
59//!   compaction/vacuum step is a follow-up for callers that require shredding.
60//! * **Coarse AEAD associated-data binding (inherited formats).** The `AEIX` format
61//!   binds only its 10-byte header as AAD; the `ACV1` cold wrapper uses empty AAD
62//!   (the `key_version` in the wrapper is not authenticated). Neither binds the
63//!   ciphertext to its file identity / redb key / entity id, so wrapped blobs are
64//!   *relocatable* by an attacker with write access (confidentiality and per-blob
65//!   integrity still hold; only cross-entity placement is unauthenticated). This is
66//!   a property of the reused #481/#3617 formats, not introduced here; binding file
67//!   id / redb key (and the `key_version`) into the AAD is a defense-in-depth
68//!   follow-up.
69//!
70//! # Crash resume
71//!
72//! An interrupted enable has NOT yet flipped the authority, so
73//! `config.encryption.enabled` is still `false` — which means the rotation resume
74//! paths ([`resume_pending_rotation`](crate::db::rotation), which gate on
75//! `enabled == true`) will NOT fire, and they additionally skip any
76//! `direction=enable` ledger outright. That is why this module ships its own
77//! [`resume_pending_enable`] reconciler (plus the pre-replay
78//! [`install_pending_enable_wal_keyring`](crate::db::rotation::install_pending_enable_wal_keyring)
79//! hook that lets the startup replay read decrypt an already-rolled WAL), both
80//! wired into `open()`.

95/// Outcome of a completed plaintext → encrypted enable migration.
96///
97/// Each flag reports whether that at-rest layer's migration pass ran (the layer
98/// was in scope). `wal_migrated`, `index_migrated`, and `checkpoint_migrated` are
99/// always `true` for a durable database (index/checkpoint ride one pass);
100/// `cold_migrated` is `true` only when a cold tier was present. The key-source
101/// reference recorded into the durable
102/// [`encryption.state`](crate::db::encryption_state) authority is echoed so the
103/// operator can confirm what the next `open()` will consult.
104#[derive(Debug, Clone, PartialEq, Eq)]
105pub struct EnableReport {
106    /// WAL segments rolled to the encrypted (v16) format.
107    pub wal_migrated: bool,
108    /// Plaintext index files wrapped into the `AEIX` format.
109    pub index_migrated: bool,
110    /// Checkpoint files covered (ride the index DEK/format wrap pass).
111    pub checkpoint_migrated: bool,
112    /// Cold-storage bare values wrapped into the `ACV1` format (only when a cold
113    /// tier is present; `false` otherwise).
114    pub cold_migrated: bool,
115    /// The non-secret key-source reference recorded into the authority
116    /// (File path / Env var name — never key bytes).
117    pub key_source: KeyProviderConfig,
118}

120/// Map the WAL seam's **double-install** rejection to a `FailedPrecondition` —
121/// enabling an already-encrypted WAL is a caller precondition failure, not an
122/// internal fault (honors the PR2 `install_wal_keyring` TODO).
123///
124/// Only the distinguishable [`StorageError::WalKeyringAlreadyInstalled`] variant
125/// is reclassified. A genuine WAL I/O / seal-and-reopen fault (a plain
126/// [`StorageError::WalError`], or anything else) is a real internal failure and
127/// is passed through UNCHANGED so it keeps its `INTERNAL` classification — it must
128/// never be mislabeled as the non-retriable "already encrypted" precondition.
129fn map_wal_install_err(e: Error) -> Error {
130    match &e {
131        Error::Storage(StorageError::WalKeyringAlreadyInstalled { reason }) => {
132            Error::FailedPrecondition(format!(
133                "cannot enable encryption: the WAL is already encrypted ({reason})"
134            ))
135        }
136        _ => e,
137    }
138}

142    ///
143    /// Sourced from `config.encryption.algorithm` (retained on the DB as
144    /// [`configured_encryption_algorithm`](AletheiaDB::configured_encryption_algorithm)
145    /// even when encryption is disabled), NOT from the absent `encryption_config`
146    /// of a plaintext database. This is the single source of truth for BOTH the
147    /// enable write and the interrupted-enable resume: the resume's wrap passes and
148    /// the ciphers `open()` builds from `config.encryption.algorithm`
149    /// (`enable_resume_ciphers`) then read the identical value, so they can never

156        self.configured_encryption_algorithm
157    }

159    /// Migrate this **plaintext** database to encrypted-at-rest under
160    /// `key_source`, in place, crash-consistently (Issue #3616 PR3).
161    ///
162    /// # ⚠️ LOUD REOPEN CONTRACT — read before calling
163    ///
164    /// This is a **reopen-centric** migration. When this call returns `Ok`, the
165    /// handle you are holding is in a deliberately **partial**, **quiesced**
166    /// runtime state:
167    ///
168    /// * **WAL** is encrypted **live** — the DEK keyring has been installed and
169    ///   every subsequent WAL append is written encrypted.
170    /// * **Index / checkpoint / cold persistence is QUIESCED** — the background
171    ///   index-persistence thread was stopped (and joined) as step 1 and is
172    ///   **not restarted by this call**. This is a structural necessity, not a
173    ///   shortcut: the [`IndexPersistenceManager`](crate::storage::index_persistence::IndexPersistenceManager)'s
174    ///   index keyring is owned **by value** (there is no live `None → Some`
175    ///   install as there is for the WAL's atomic-swap cell), so a handle created
176    ///   plaintext can never *begin* writing encrypted index files. Restarting a
177    ///   persisting worker in-process would therefore write **plaintext** index
178    ///   files over a database whose authority now says "encrypted" — the exact
179    ///   corruption this engine exists to prevent. The worker is thus respawned
180    ///   only by the mandatory **reopen** (a fresh manager built with the index
181    ///   keyring), which is where "stop → migrate → respawn" completes.
182    ///
183    /// ## The quiesced window — NO persistence is permitted through this handle
184    ///
185    /// Between this call returning and the reopen, this handle must perform **no
186    /// index/checkpoint/cold persistence at all** — neither the background thread
187    /// (stopped + joined as step 1, not restarted) nor an **explicit
188    /// [`persist_indexes`](AletheiaDB::persist_indexes) call**. The reason is
189    /// structural: the live WAL is now encrypted, but this handle's index manager
190    /// still carries a **plaintext** keyring (there is no live `None → Some`
191    /// index-keyring install). A persist would therefore write **plaintext** index
192    /// files over the freshly-wrapped `AEIX` snapshot — the exact corruption this
193    /// engine prevents. To make that impossible rather than merely discouraged,
194    /// [`persist_indexes`](AletheiaDB::persist_indexes) is **fail-closed** on a
195    /// post-enable handle (it returns a `FailedPrecondition` telling you to reopen)
196    /// so no code path can silently corrupt the encrypted snapshot.
197    ///
198    /// Continuing to WRITE through the returned handle is likewise **not
199    /// supported** in v1 (index mutations would not be persisted by this handle;
200    /// they survive only via the encrypted WAL until reopen). **You MUST reopen the
201    /// database** (drop this handle and call [`AletheiaDB::open`]) to get a
202    /// fully-operational encrypted instance: the next `open()` reads the flipped
203    /// [`encryption.state`](crate::db::encryption_state) authority, brings every
204    /// layer up under the cipher, and restarts the background persistence thread.
205    ///
206    /// # Errors
207    ///
208    /// Returns a structured error (never a partial silent success) when:
209    /// * index persistence is not enabled (an ephemeral / in-memory database
210    ///   cannot be migrated — `FailedPrecondition`);
211    /// * the database is already encrypted (`FailedPrecondition` — use key
212    ///   rotation, not enable);
213    /// * `key_source` is a Passphrase/KMS/Vault backend (the authority + ledger
214    ///   can only persist a File/Env reference — `FailedPrecondition`);
215    /// * any layer migration (WAL / index / checkpoint / cold) or the durable
216    ///   authority flip fails.
217    ///
218    /// On any error the binding order guarantees the database is left either fully
219    /// plaintext (authority never flipped) or resumable via
220    /// [`resume_pending_enable`] on the next `open()` — never a silently
221    /// half-encrypted state that reads as plaintext.
222    pub fn enable_encryption(&mut self, key_source: KeyProviderConfig) -> Result<EnableReport> {
223        // Drive the whole migration off per-field `LayerStatus` checks in the
224        // rotation ledger — NEVER off a positional index or a count of layers.
225
226        // === Step 0: preconditions (no side effects — run BEFORE quiesce) ============
227        let manager = self.persistence_manager.clone().ok_or_else(|| {
228            Error::FailedPrecondition(
229                "cannot enable encryption on an ephemeral (in-memory) database: no durable \
230                 at-rest bytes or authority file to migrate. Open a durable database first."
231                    .to_string(),
232            )
233        })?;
234
235        if self.encryption_manager.is_some() || self.wal.is_encrypted() {
236            return Err(Error::FailedPrecondition(
237                "database is already encrypted; use key rotation, not enable".to_string(),
238            ));
239        }
240        if read_encryption_state(manager.base_path())?
241            .map(|state| state.enabled)
242            .unwrap_or(false)
243        {
244            return Err(Error::FailedPrecondition(
245                "the durable encryption authority already records this database as encrypted"
246                    .to_string(),
247            ));
248        }
249
250        // Only File/Env sources round-trip through the ledger + authority.
251        match &key_source {
252            KeyProviderConfig::File { .. } | KeyProviderConfig::Env { .. } => {}
253            other => {
254                let (provider_type, _) = other.describe();
255                return Err(Error::FailedPrecondition(format!(
256                    "enabling encryption with a {provider_type} key source is not supported \
257                     (only file/env references can be persisted without leaking a secret)"
258                )));
259            }
260        }
261
262        // Is a cold tier in scope? Its bare values are wrapped to `ACV1` below.
263        let cold_in_scope = self.historical.read().has_tiered_storage();
264
265        // Build the WAL keyring EARLY so an unreadable/short key fails fast, before
266        // the background thread is stopped (no side effects if this errors).
267        let algorithm = self.enable_algorithm();
268        let keyring = build_enable_wal_keyring(&key_source, algorithm)?;
269
270        // === Step 1: quiesce the background index-persistence thread =================
271        // Stop + join. The worker's shutdown final-persist runs while the whole DB
272        // is still plaintext, so it is a safe plaintext write. NOT restarted here
273        // (see the reopen contract) — respawn is the reopen's fresh worker.
274        if let Some(tracker) = self.persistence_tracker.as_ref() {
275            tracker.signal_shutdown();
276        }
277        if let Some(handle) = self.persistence_thread_handle.take() {
278            let _ = handle.join();
279        }
280
281        // === Step 1b: synchronous full persist while STILL PLAINTEXT =================
282        // Capture ALL pre-enable state (current + historical, as of the current WAL
283        // frontier) into the durable index snapshot NOW, before the WAL is sealed.
284        // The index wrap below turns this snapshot into `AEIX`, so afterwards the
285        // ENCRYPTED snapshot holds every pre-enable record — which is what makes it
286        // safe to RETIRE the pre-enable plaintext WAL segments (Step 2c) without any
287        // data loss (reopen reconstructs from the encrypted snapshot, not the deleted
288        // plaintext WAL). Runs while the WAL is still plaintext, so the fail-closed
289        // `persist_indexes` guard (post-enable handle) does not apply. This is a
290        // superset of the worker's shutdown final-persist above — belt-and-suspenders.
291        self.persist_indexes()?;
292
293        // === Step 2: durable ledger (breadcrumb #1) then migrate every layer =========
294        // WAL is always Pending; index + checkpoint are Pending (a durable database
295        // always has an index dir to wrap); cold is Pending iff a cold tier exists.
296        // The quiesce above ran the worker's shutdown final-persist while the DB was
297        // still plaintext, so the index dir now holds a fresh PLAINTEXT snapshot the
298        // wrap pass converts.
299        write_enable_ledger(&manager, &key_source, true, cold_in_scope)?;
300
301        // WAL: install the keyring (seal plaintext v13 → store → reopen encrypted
302        // v16) via the PR2 seam, then record completion (breadcrumb #2).
303        self.wal
304            .install_wal_keyring(keyring)
305            .map_err(map_wal_install_err)?;
306        mark_wal_complete(&manager)?;
307
308        // Index + checkpoint: wrap every bare plaintext index file into `AEIX` under
309        // the index DEK, then record completion (breadcrumb #3).
310        wrap_enable_index_files(&manager, &key_source, algorithm)?;
311        mark_index_complete(&manager)?;
312
313        // WAL plaintext retire: now that the ENCRYPTED (`AEIX`) index snapshot durably
314        // holds every pre-enable record (Step 1b persist → this wrap), retire the
315        // sealed pre-enable PLAINTEXT (v13) WAL segments so no cleartext survives at
316        // rest (breadcrumb #3b). Idempotent + resumable: a crash mid-retire leaves
317        // `wal_retire=Pending` and the resume re-runs it. The fresh encrypted (v16)
318        // active segment is kept; reopen reconstructs pre-enable state from the
319        // encrypted snapshot. Only in scope when the index snapshot exists
320        // (`enable_scope` sets `wal_retire=Pending` iff index is in scope).
321        retire_enable_plaintext_wal(&self.wal)?;
322        mark_wal_retire_complete(&manager)?;
323
324        // Cold: wrap every bare stored value into `ACV1` under the cold DEK on the
325        // live (plaintext-keyring) cold store, then record completion (breadcrumb
326        // #4). Byte-preserving; full encrypted cold reads resume at the next open()
327        // (the live store's keyring stays `None` — see the reopen contract).
328        if cold_in_scope {
329            let tiered = self.historical.read().tiered_storage_arc().ok_or_else(|| {
330                Error::FailedPrecondition(
331                    "cold tier vanished between precondition check and migration".to_string(),
332                )
333            })?;
334            let cold_cipher = build_enable_cold_cipher(&key_source, algorithm)?;
335            tiered
336                .cold_storage()
337                .wrap_plaintext_cold_values(&cold_cipher, ENABLE_KEY_VERSION)?;
338            mark_cold_complete(&manager)?;
339        }
340
341        // === Step 3: flip the authority BEFORE clearing the ledger (binding order) ===
342        // (breadcrumb #5) A crash after this but before the clear resumes via
343        // `resume_pending_enable`.
344        // Pin the RESOLVED concrete algorithm (the same one every wrap pass above
345        // wrote under) so the reopen rebuilds the identical cipher.
346        write_encryption_state_durable(
347            manager.base_path(),
348            &EncryptionState::enabled_with_algorithm(key_source.clone(), algorithm),
349        )?;
350
351        // === Step 4: clear the ledger (breadcrumb #6) ================================
352        clear_rotation_state(&manager);
353
354        Ok(EnableReport {
355            wal_migrated: true,
356            index_migrated: true,
357            checkpoint_migrated: true,
358            cold_migrated: cold_in_scope,
359            key_source,
360        })
361    }

363    /// Resume an interrupted plaintext → encrypted enable migration at `open()`
364    /// time, if one is pending (Issue #3616 PR3).
365    ///
366    /// Wired into [`with_unified_config`](crate::AletheiaDB::with_unified_config)
367    /// alongside the rotation resume paths, but distinct from them: an interrupted
368    /// enable has NOT yet flipped the [`encryption.state`](crate::db::encryption_state)
369    /// authority, so `config.encryption.enabled` is still `false` and
370    /// [`resume_pending_rotation`](crate::db::rotation) never fires (and skips a
371    /// `direction=enable` ledger anyway). This reconciler recognizes the
372    /// enable-scope ledger and completes the migration idempotently, driving off
373    /// each layer's per-field `LayerStatus`.
374    ///
375    /// By the time this runs at startup the pre-replay
376    /// [`install_pending_enable_wal_keyring`](crate::db::rotation::install_pending_enable_wal_keyring)
377    /// hook has already installed the WAL keyring when the on-disk WAL was
378    /// encrypted, so the replay read decrypted correctly; here we finish any
379    /// still-`Pending` WAL work, then flip the authority and clear the ledger.
380    ///
381    /// **Guarded no-op:** returns `Ok(())` immediately when no durable
382    /// pending-enable ledger exists (the overwhelmingly common startup path), so
383    /// wiring it unconditionally into `open()` costs at most one ledger probe.
384    ///
385    /// # Errors
386    ///
387    /// Propagates a fail-closed error if a present ledger is corrupt, a WAL
388    /// keyring cannot be built/installed, or a not-yet-implemented layer
389    /// (index/checkpoint/cold) is `Pending` — a corrupt/undecryptable state must
390    /// abort startup loudly rather than be treated as "no migration pending".
391    pub(crate) fn resume_pending_enable(&self) -> Result<()> {
392        let Some(manager) = self.persistence_manager.as_ref() else {
393            return Ok(());
394        };
395        let Some(view) = read_enable_ledger(manager)? else {
396            return Ok(());
397        };
398
399        // WAL: ensure the keyring is installed + rolled, then record completion.
400        // At startup the pre-read hook installs it when the WAL is already
401        // encrypted on disk; if it is still plaintext (crash before the roll),
402        // install now to seal -> roll -> encrypt.
403        if view.wal_pending {
404            if !self.wal.is_encrypted() {
405                let keyring = build_enable_wal_keyring(&view.new_source, self.enable_algorithm())?;
406                self.wal
407                    .install_wal_keyring(keyring)
408                    .map_err(map_wal_install_err)?;
409            }
410            mark_wal_complete(manager)?;
411        }
412
413        // Index + checkpoint: complete the plaintext -> `AEIX` wrap pass INLINE,
414        // BEFORE the caller reads the index directory back (`open()` runs this
415        // before `load_indexes`). The pass is idempotent — a crash mid-pass left a
416        // mix of plaintext + `AEIX` files, and re-running wraps only the remaining
417        // plaintext ones. The manager was built under the enable index DEK on this
418        // startup (see `enable_resume_ciphers`), so both the wrap writes and the
419        // subsequent index load read the encrypted bytes correctly.
420        if view.index_pending || view.checkpoint_pending {
421            wrap_enable_index_files(manager, &view.new_source, self.enable_algorithm())?;
422            mark_index_complete(manager)?;
423        }
424
425        // WAL plaintext retire (resume): retire the pre-enable PLAINTEXT (v13) WAL
426        // segments once the ENCRYPTED (`AEIX`) index snapshot holds the pre-enable
427        // state (index Complete). Lossless on resume: (a) the original enable ran a
428        // synchronous persist BEFORE writing this ledger, so the encrypted snapshot
429        // durably holds every pre-enable record, and (b) startup already read every
430        // WAL segment into memory (`startup_wal_entries`, before this runs), so the
431        // subsequent differential replay re-covers them regardless — deleting the
432        // segment FILES here cannot lose an in-memory entry. Gated on `index_complete`
433        // so a (synthetic) no-index-snapshot enable never deletes plaintext WAL.
434        // Idempotent: re-runs after a crash mid-retire. Re-read to observe the index
435        // completion just recorded.
436        if let Some(mid) = read_enable_ledger(manager)?
437            && mid.wal_retire_pending
438            && mid.index_complete
439        {
440            retire_enable_plaintext_wal(&self.wal)?;
441            mark_wal_retire_complete(manager)?;
442        }
443
444        // Re-read the ledger to reflect the index/checkpoint completions just
445        // recorded, then decide on the flip from the FRESH per-field state (never a
446        // stale in-memory view). If any non-WAL layer is still `Pending` it can only
447        // be cold: the cold store is not wired onto `self.historical` at this point
448        // in `open()` (it is constructed AFTER index load), so DEFER the cold wrap +
449        // the authority flip + the ledger clear to `resume_pending_enable_cold`,
450        // which runs once the cold store exists. Leaving the ledger present is the
451        // binding-order guarantee: the authority is not flipped until every layer,
452        // cold included, is settled.
453        let Some(fresh) = read_enable_ledger(manager)? else {
454            return Ok(());
455        };
456        if !fresh.non_wal_layers_settled() {
457            return Ok(());
458        }
459
460        // Every non-WAL layer is settled and there is no cold work to defer: flip
461        // the authority BEFORE clearing the ledger (idempotent if already flipped —
462        // the flip->clear-gap resume case).
463        write_encryption_state_durable(
464            manager.base_path(),
465            &EncryptionState::enabled_with_algorithm(
466                fresh.new_source.clone(),
467                self.enable_algorithm(),
468            ),
469        )?;
470        clear_rotation_state(manager);
471        Ok(())
472    }

474    /// Finish an interrupted enable migration's COLD layer at `open()` time, once
475    /// the cold store has been wired onto `self.historical` (Issue #3616 PR3).
476    ///
477    /// [`resume_pending_enable`] runs before the cold tier is constructed, so it
478    /// cannot wrap cold values; it therefore DEFERS the cold wrap, the authority
479    /// flip, and the ledger clear to this method, which `open()` calls after the
480    /// cold store is set. This preserves the binding order — the authority is
481    /// flipped only after **every** layer (cold included) is settled.
482    ///
483    /// The cold store is built under the enable cold DEK on this startup (see
484    /// [`enable_resume_ciphers`](crate::db::rotation::enable_resume_ciphers)), so
485    /// the wrap-only pass rewrites each bare value to `ACV1` and the resumed
486    /// session reads its own wrapped values. Idempotent / resumable: a value
487    /// already wrapped at the enable version is skipped, and the pass advances a
488    /// durable redb cursor so a crash mid-pass resumes with no double-encrypt.
489    ///
490    /// **Guarded no-op:** returns `Ok(())` when no pending-enable ledger exists or
491    /// its cold layer is not `Pending`.
492    pub(crate) fn resume_pending_enable_cold(&self) -> Result<()> {
493        let Some(manager) = self.persistence_manager.as_ref() else {
494            return Ok(());
495        };
496        let Some(view) = read_enable_ledger(manager)? else {
497            return Ok(());
498        };
499        if !view.cold_pending {
500            return Ok(());
501        }
502
503        // Cold is Pending but the store is not wired: the ledger claims a cold tier
504        // that this open() did not construct. Fail closed rather than flip the
505        // authority while cold values remain bare under it.
506        let tiered = self.historical.read().tiered_storage_arc().ok_or_else(|| {
507            Error::FailedPrecondition(
508                "pending enable ledger records a cold layer, but no cold tier is configured on \
509                 this open(); reopen with the cold tier enabled so the migration can complete"
510                    .to_string(),
511            )
512        })?;
513        let cold_cipher = build_enable_cold_cipher(&view.new_source, self.enable_algorithm())?;
514        tiered
515            .cold_storage()
516            .wrap_plaintext_cold_values(&cold_cipher, ENABLE_KEY_VERSION)?;
517        mark_cold_complete(manager)?;
518
519        // Every layer is now settled: binding order — flip the authority BEFORE
520        // clearing the ledger (idempotent if already flipped).
521        write_encryption_state_durable(
522            manager.base_path(),
523            &EncryptionState::enabled_with_algorithm(
524                view.new_source.clone(),
525                self.enable_algorithm(),
526            ),
527        )?;
528        clear_rotation_state(manager);
529        Ok(())
530    }

532    /// Fail LOUDLY at startup when an interrupted enable recorded a cold layer as
533    /// `Pending` but this `open()` will NOT construct a cold tier (Issue #3616 PR3).
534    ///
535    /// [`resume_pending_enable_cold`](Self::resume_pending_enable_cold)'s own
536    /// fail-closed guard only runs when the cold-init block is entered. If the
537    /// operator reopens with the cold tier disabled or dropped (a trimmed config, a
538    /// moved cold path), that block is skipped and the guard is **unreachable**, so
539    /// the enable ledger would otherwise wedge forever — `resume_pending_enable`
540    /// defers (cold still `Pending` → `non_wal_layers_settled() == false`), the
541    /// authority is never flipped, and nothing tells the operator the enable is
542    /// stuck. This converts that silent limbo into the same actionable
543    /// `FailedPrecondition` the in-block guard emits. Called on the startup branch
544    /// that does NOT build a cold tier. A guarded no-op when no pending-enable
545    /// ledger exists or its cold layer is not `Pending`.
546    pub(crate) fn fail_if_pending_enable_cold_without_tier(&self) -> Result<()> {
547        let Some(manager) = self.persistence_manager.as_ref() else {
548            return Ok(());
549        };
550        let Some(view) = read_enable_ledger(manager)? else {
551            return Ok(());
552        };
553        if view.cold_pending {
554            return Err(Error::FailedPrecondition(
555                "pending enable ledger records a cold layer, but no cold tier is configured on \
556                 this open(); reopen with the cold tier enabled so the migration can complete"
557                    .to_string(),
558            ));
559        }
560        Ok(())
561    }

663    /// Count the index files under `dir`, returning (total, plaintext_count,
664    /// aeix_count) — walking recursively and skipping atomic-write scratch files.
665    fn classify_index_files(dir: &Path) -> (usize, usize, usize) {
666        use crate::storage::index_persistence::common::is_encrypted_index;
667        fn walk(dir: &Path, total: &mut usize, plain: &mut usize, aeix: &mut usize) {
668            if !dir.exists() {
669                return;
670            }
671            for e in std::fs::read_dir(dir).unwrap() {
672                let p = e.unwrap().path();
673                if p.is_dir() {
674                    walk(&p, total, plain, aeix);
675                    continue;
676                }
677                let name = p.file_name().unwrap().to_string_lossy().into_owned();
678                if name.ends_with(".tmp")
679                    || name.contains(".tmp.")
680                    || name.starts_with(".aeix-usearch-tmp-")
681                {
682                    continue;
683                }
684                *total += 1;
685                let bytes = std::fs::read(&p).unwrap();
686                if is_encrypted_index(&bytes) {
687                    *aeix += 1;
688                } else {
689                    *plain += 1;
690                }
691            }
692        }
693        let (mut total, mut plain, mut aeix) = (0, 0, 0);
694        walk(dir, &mut total, &mut plain, &mut aeix);
695        (total, plain, aeix)
696    }
