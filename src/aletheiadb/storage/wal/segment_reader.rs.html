1//! WAL Segment Reader.
2//!
3//! This module provides standalone functions for reading WAL segments from disk
4//! for recovery purposes. It does not require any WAL writer state.
5//!
6//! # Segment Format
7//!
8//! Each segment file on disk has the following binary layout:
9//!
10//! ```text
11//!  Offset  Size  Field
12//!  ──────  ────  ──────────────────────────────────────────────────
13//!       0     4  Magic bytes: b"GWAL"  (WAL_MAGIC)
14//!       4     1  Format version: 1 (plaintext) or 2 (encrypted)
15//!       5     …  Entry frames (repeated until end of file)
16//! ```
17//!
18//! **Entry frame (version 1 – plaintext)**:
19//! ```text
20//!  [bincode-serialised WalEntry bytes]
21//! ```
22//! Entries are length-prefixed by `bincode` (8-byte little-endian usize).
23//!
24//! **Entry frame (version 2 – encrypted)**:
25//! ```text
26//!  [4-byte LE u32 entry length][encrypted entry bytes]
27//! ```
28//! The header (magic + version) is always plaintext; only the entry frames
29//! are encrypted in version 2.
30//!
31//! See the `WAL_MAGIC`, `WAL_VERSION`, `WAL_VERSION_ENCRYPTED`, and
32//! `WAL_HEADER_SIZE` constants defined below for the associated values.
33//!
34//! # Memory Efficiency
35//!
36//! This module uses memory-mapped I/O (`memmap2`) to read WAL segments efficiently.
37//! Instead of loading entire segment files (default 64MB) into memory, memory-mapped
38//! files allow the OS to handle paging automatically. This provides several benefits:
39//!
40//! - **Lower memory usage**: OS pages in data as needed, not all at once
41//! - **Better caching**: OS can cache frequently accessed pages
42//! - **Automatic eviction**: OS evicts pages under memory pressure
43//! - **Reduced recovery memory**: With 10 segments, peak memory drops from 640MB+ to O(working set)
44//!
45//! See issue #216 for details.

171/// WAL format version that serializes node/edge/constraint **label** strings as
172/// length-prefixed UTF-8 (`[len: u32-LE][utf8 bytes]`) and re-interns them on
173/// read, instead of persisting a raw [`InternedString`] id (Issue #3506).
174///
175/// A strict superset of [`WAL_VERSION_DESTRUCTIVE_PROVENANCE`]: it keeps every
176/// prior field (tx framing, tombstone/retraction `version_id`, destructive-op
177/// provenance) and only changes how the label field of `CreateNode`,
178/// `CreateEdge`, `UpdateNode`, `UpdateEdge`, `DeclareUniqueConstraint`, and
179/// `DropUniqueConstraint` is encoded. Prior versions wrote the label as a raw
180/// 4-byte interner id and replayed it via [`InternedString::from_raw`] WITHOUT
181/// re-interning the underlying string — correct only when the replaying
182/// process reproduced the exact id→string layout of the writer. In a
183/// non-identity interner layout (multiple `AletheiaDB` instances sharing the
184/// process-global interner, repeated open/close, or the WAL-only replay path
185/// that performs no interner restore) a raw-id label silently resolved to the
186/// wrong string. v13+ segments carry the string itself, so labels are correct
187/// under any interner layout, exactly as property keys/values already are.
188///
189/// The [`carries_string_labels`] gate is an independent monotonic `>=` boolean
190/// on the same version byte, composing with the framing/delete-version-id/
191/// destructive-provenance gates. ≤v12 segments keep the raw-id decode path
192/// (best-effort, identity-layout only — we cannot retroactively recover a
193/// string that was never written); v13+ segments are unconditionally correct.
194/// Bumping the header version makes an older reader reject the file cleanly
195/// rather than mis-length the variable-width label payload, following the
196/// #3224/#3406/#3413/#3427 precedent.
197pub(crate) const WAL_VERSION_STRING_LABELS: u8 = 13;

209/// WAL format version for encrypted segments that carry a 4-byte `key_version`
210/// in an EXTENDED (9-byte) header, enabling dual-generation full-MEK key
211/// rotation of the WAL layer (Issue #3617).
212///
213/// Header layout (little-endian):
214/// ```text
215///   [magic "GWAL":4][format version:1 = 16][key_version:u32 LE:4][frames…]
216/// ```
217/// (Legacy encrypted/plaintext segments keep the 5-byte header with no
218/// `key_version`.) The decrypted entry payload uses the CURRENT plaintext layout
219/// ([`WAL_VERSION_STRING_LABELS`], via [`payload_version`]); the `key_version`
220/// selects which WAL DEK generation decrypts the frames, so a rotation can write
221/// new appends under a new DEK while legacy segments still replay under the old
222/// one. An older binary rejects this version cleanly ("Unsupported WAL version")
223/// rather than misparsing the extended header.
224///
225/// # Version-byte parity invariant
226///
227/// Encrypted WAL versions are EVEN by contract (2,4,…,14) and plaintext ones
228/// ODD (1,3,…,13); the encrypted-segment recovery tests assert every encrypted
229/// segment's version byte is even. `WAL_VERSION_MAX + 1` (15) is ODD, so this
230/// keyversioned *encrypted* container uses `WAL_VERSION_MAX + 2` (= 16, even)
231/// to preserve that invariant. Version 15 was never written to disk (this
232/// container is unreleased), so it stays an unused reserved gap between
233/// `WAL_VERSION_MAX` (14) and this value — a v15 segment is correctly rejected
234/// as an unsupported/unknown version.
235pub(crate) const WAL_VERSION_ENCRYPTED_KEYVERSIONED: u8 = WAL_VERSION_MAX + 2;

237/// Maximum supported WAL version (inclusive), including the variable-length
238/// `KEYVERSIONED` container (Issue #3617). Used only in the "max supported"
239/// diagnostic on the unsupported-version reject; the actual accept/reject

241/// v15 gap between `WAL_VERSION_MAX` (14) and the keyversioned container (16).
242const WAL_VERSION_KEYVERSIONED_MAX: u8 = WAL_VERSION_ENCRYPTED_KEYVERSIONED;

248/// Returns `true` if `ver` is a WAL segment format version this build can
249/// decode.
250///
251/// Supported versions are the contiguous fixed-header families
252/// `1..=WAL_VERSION_MAX` (14) plus the variable-header keyversioned container
253/// [`WAL_VERSION_ENCRYPTED_KEYVERSIONED`] (16). Renumbering the keyversioned
254/// container from 15 to 16 — to preserve the encrypted-versions-are-EVEN parity
255/// invariant (Issue #3617) — leaves **15 an unused reserved gap** with no
256/// defined on-disk format; a v15 segment is therefore rejected as unsupported,
257/// exactly like any version above the max. (No writer ever emits v15, so this
258/// only guards against corruption or a forward-incompatible file.)
259#[inline]
260fn is_supported_segment_version(ver: u8) -> bool {
261    ver <= WAL_VERSION_MAX || ver == WAL_VERSION_ENCRYPTED_KEYVERSIONED
262}

321/// Map a segment/container format version to the logical *payload* version
322/// used to gate field parsing (e.g. `version >= WAL_VERSION_PROVENANCE`).
323///
324/// Encrypted versions describe the on-disk *container* (length-prefixed +
325/// encrypted), not the entry payload layout once decrypted; this maps them
326/// back to the plaintext version whose entry layout they share.
327#[inline]
328fn payload_version(version: u8) -> u8 {
329    match version {
330        WAL_VERSION_ENCRYPTED => WAL_VERSION,
331        WAL_VERSION_ENCRYPTED_PROVENANCE => WAL_VERSION_PROVENANCE,
332        WAL_VERSION_ENCRYPTED_PROVENANCE_PRINCIPAL => WAL_VERSION_PROVENANCE_PRINCIPAL,
333        WAL_VERSION_ENCRYPTED_TX_FRAMING => WAL_VERSION_TX_FRAMING,
334        WAL_VERSION_ENCRYPTED_DELETE_VERSION_ID => WAL_VERSION_DELETE_VERSION_ID,
335        WAL_VERSION_ENCRYPTED_DESTRUCTIVE_PROVENANCE => WAL_VERSION_DESTRUCTIVE_PROVENANCE,
336        WAL_VERSION_ENCRYPTED_STRING_LABELS => WAL_VERSION_STRING_LABELS,
337        // The keyversioned container (Issue #3617) only prefixes a key_version
338        // to the header; its decrypted entry payload uses the CURRENT plaintext
339        // layout, exactly like WAL_VERSION_ENCRYPTED_STRING_LABELS.
340        WAL_VERSION_ENCRYPTED_KEYVERSIONED => WAL_VERSION_STRING_LABELS,
341        v => v,
342    }
343}

345/// The `WAL_VERSION_ENCRYPTED_KEYVERSIONED` header length (Issue #3617): the
346/// 5-byte legacy header plus the 4-byte `key_version`.
347pub(crate) const WAL_KEYVERSIONED_HEADER_SIZE: usize = WAL_HEADER_SIZE + WAL_KEYVERSION_FIELD_SIZE;

349/// Decode the segment header layout for a known-supported `version`.
350///
351/// Returns `(header_len, key_version)` — the number of leading header bytes
352/// before the first entry frame, and the stamped `key_version` for a
353/// [`WAL_VERSION_ENCRYPTED_KEYVERSIONED`] (v16) segment (`None` for every legacy
354/// 5-byte header). `buffer` must already have passed the magic + version-bound
355/// checks. Errors only when a v16 header is truncated before its 4-byte
356/// `key_version`.
357fn decode_header_layout(version: u8, buffer: &[u8]) -> Result<(usize, Option<u32>)> {
358    if version == WAL_VERSION_ENCRYPTED_KEYVERSIONED {
359        if buffer.len() < WAL_KEYVERSIONED_HEADER_SIZE {
360            return Err(StorageError::CorruptedData(
361                "Keyversioned WAL segment header truncated before key_version".to_string(),
362            )
363            .into());
364        }
365        let kv = u32::from_le_bytes([buffer[5], buffer[6], buffer[7], buffer[8]]);
366        Ok((WAL_KEYVERSIONED_HEADER_SIZE, Some(kv)))
367    } else {
368        Ok((WAL_HEADER_SIZE, None))
369    }
370}

372/// How a caller supplies WAL DEK ciphers to the segment reader (Issue #3617).
373///
374/// Recovery must decrypt each segment under the WAL DEK generation named by its
375/// header `key_version`; during a full-MEK rotation two generations are live at
376/// once. This resolver lets the reader select the right cipher per segment while
377/// keeping the legacy single-cipher entry points (`Option<&Arc<dyn Cipher>>`)
378/// working unchanged.
379pub enum WalCipherSource<'a> {
380    /// Plaintext WAL — no cipher.
381    None,
382    /// A single cipher used for every segment regardless of `key_version`
383    /// (the never-rotated / legacy single-generation callers).
384    Single(&'a Arc<dyn crate::encryption::cipher::Cipher>),
385    /// A multi-generation keyring: legacy segments resolve to the pre-rotation
386    /// (oldest) generation, keyversioned segments to the named generation.
387    Keyring(&'a crate::encryption::wal_encryption::WalKeyring),
388}
389
390impl WalCipherSource<'_> {
391    /// Whether any cipher material is present (an encrypted segment cannot be
392    /// read when this is `false`).
393    fn is_present(&self) -> bool {
394        !matches!(self, WalCipherSource::None)
395    }
396
397    /// Resolve the decryption cipher for a segment, given the `key_version` read
398    /// from its header (`None` for a legacy segment carrying no key-version).
399    fn resolve(
400        &self,
401        key_version: Option<u32>,
402    ) -> Option<Arc<dyn crate::encryption::cipher::Cipher>> {
403        match self {
404            WalCipherSource::None => None,
405            WalCipherSource::Single(c) => Some((*c).clone()),
406            WalCipherSource::Keyring(k) => k.cipher_for_segment(key_version),
407        }
408    }
409}
410
411impl<'a> From<Option<&'a Arc<dyn crate::encryption::cipher::Cipher>>> for WalCipherSource<'a> {
412    fn from(cipher: Option<&'a Arc<dyn crate::encryption::cipher::Cipher>>) -> Self {
413        match cipher {
414            Some(c) => WalCipherSource::Single(c),
415            None => WalCipherSource::None,
416        }
417    }
418}

420/// The newest *plaintext* WAL entry payload version — the exact shape that
421/// `serialization::serialize_operation_into` writes and that
422/// `flush_coordinator` stamps on new plaintext segments
423/// (currently [`WAL_VERSION_DELETE_VERSION_ID`], v9).
424///
425/// Derived from [`WAL_VERSION_MAX`] (the newest *encrypted* container version,
426/// v10) via [`payload_version`], so it can NEVER lag a format bump: any change
427/// that raises `WAL_VERSION_MAX` and extends `payload_version`'s mapping is
428/// tracked automatically. Round-trip harnesses that serialize a fresh entry and
429/// re-parse it (e.g. the `wal_entry_parsing` fuzz target via
430/// `crate::fuzzing::wal::parse_current_entry`) MUST parse at this version:
431/// parsing at a stale version skips the framing (#3413, v7) and delete/retract
432/// `version_id` (#3406, v9) bytes the serializer wrote, misaligns the buffer,
433/// and fails the entry checksum.
434///
435/// History of the newest plaintext version: #3224→3, #3421→5, #3413→7,
436/// #3406→9, #3427→11, #3506→13. Bump on every WAL plaintext format increase.
437#[inline]
438// Only referenced by the fuzz-only `crate::fuzzing` module, so it is compiled
439// only under `any(fuzzing, feature = "fuzzing")`; on non-fuzzing builds it is
440// omitted entirely (no dead-code hit) while fuzz targets still get it.
441#[cfg(any(fuzzing, feature = "fuzzing"))]
442pub(crate) fn newest_plaintext_wal_version() -> u8 {
443    payload_version(WAL_VERSION_MAX)
444}

498/// This function scans the directory for segment files (*.log), reads them in order,
499/// and returns all entries with LSN >= start_lsn. If a cipher is provided, version 2
500/// (encrypted) segments are decrypted transparently. Version 1 (plaintext) segments
501/// are always read without decryption regardless of the cipher parameter.
502///
503/// # Arguments
504///
505/// * `wal_dir` - Path to the WAL directory containing segment files
506/// * `start_lsn` - Only entries with LSN >= this value are returned
507/// * `cipher` - Optional cipher for decrypting version 2 segments
508///
509/// # Returns
510///
511/// A vector of WAL entries sorted by LSN.
512pub fn read_entries_from_dir_with_cipher(
513    wal_dir: &Path,
514    start_lsn: LSN,
515    cipher: Option<&Arc<dyn crate::encryption::cipher::Cipher>>,
516) -> Result<Vec<WalEntry>> {
517    // Default recovery policy: tolerate a crash-torn trailing entry in the
518    // FINAL segment (Issue #3433). Operators who prefer fail-stop recovery opt
519    // out via the `tolerate_torn_tail = false` recovery config flag, which
520    // reaches this reader through `read_entries_from_dir_with_options`.
521    read_entries_from_dir_with_options(wal_dir, start_lsn, cipher, true)
522}

524/// Read all WAL entries from a directory with optional decryption and an
525/// explicit crash-torn-tail recovery policy (Issue #3433).
526///
527/// When `tolerate_torn_tail` is `true` (the default), an undecodable trailing
528/// entry in the **final** segment — the shape a crash during append leaves: a
529/// zeroed/garbage op-type byte, a mid-field truncation, or a checksum mismatch
530/// on a half-written payload — is treated as end-of-log: everything decoded
531/// before it is applied, a WARNING is logged (segment path + byte offset +
532/// underlying error), and the read stops. This generalizes #3413's
533/// truncation-only tolerance to every crash-torn shape.
534///
535/// The tolerance is strictly **tail-scoped**:
536/// * corruption in a NON-final segment (a newer segment exists past it) always
537///   hard-errors — that is real damage, not a torn append;
538/// * for encrypted (length-prefixed) segments, an undecodable frame that is
539///   FOLLOWED BY a valid frame in the final segment also hard-errors (it is
540///   resyncable mid-log corruption). Plaintext entries carry no per-entry
541///   length prefix, so once an entry is undecodable a following entry cannot be
542///   found — for plaintext, an undecodable entry in the final segment is
543///   therefore unavoidably treated as the tail (documented asymmetry).
544///
545/// When `tolerate_torn_tail` is `false`, ANY parse failure hard-errors, exactly
546/// as a strict per-segment [`read_segment`] does — fail-stop recovery.
547pub fn read_entries_from_dir_with_options(
548    wal_dir: &Path,
549    start_lsn: LSN,
550    cipher: Option<&Arc<dyn crate::encryption::cipher::Cipher>>,
551    tolerate_torn_tail: bool,
552) -> Result<Vec<WalEntry>> {
553    read_entries_from_dir_with_source(wal_dir, start_lsn, &cipher.into(), tolerate_torn_tail)
554}

556/// Read all WAL entries from a directory using a multi-generation
557/// [`WalKeyring`](crate::encryption::wal_encryption::WalKeyring) (Issue #3617).
558///
559/// The dual-generation recovery entry point: a directory holding both old-DEK
560/// (legacy or keyversioned) segments and new-DEK keyversioned segments — the
561/// mixed state an in-flight full-MEK WAL rotation leaves — decrypts every
562/// segment under the WAL DEK generation its header names. `None` reads a
563/// plaintext WAL exactly like the single-cipher path with `None`.
564pub fn read_entries_from_dir_with_keyring(
565    wal_dir: &Path,
566    start_lsn: LSN,
567    keyring: Option<&crate::encryption::wal_encryption::WalKeyring>,
568    tolerate_torn_tail: bool,
569) -> Result<Vec<WalEntry>> {
570    let source = match keyring {
571        Some(k) => WalCipherSource::Keyring(k),
572        None => WalCipherSource::None,
573    };
574    read_entries_from_dir_with_source(wal_dir, start_lsn, &source, tolerate_torn_tail)
575}

577fn read_entries_from_dir_with_source(
578    wal_dir: &Path,
579    start_lsn: LSN,
580    source: &WalCipherSource<'_>,
581    tolerate_torn_tail: bool,
582) -> Result<Vec<WalEntry>> {
583    let mut entries = Vec::new();
584
585    // Only the FINAL segment is allowed to tolerate a torn trailing entry, and
586    // only when the caller's recovery policy leaves tolerance on.
587    let segment_paths = sorted_segment_paths(wal_dir);
588    let last_idx = segment_paths.len().saturating_sub(1);
589    for (i, (_, path)) in segment_paths.iter().enumerate() {
590        let segment_tolerates = tolerate_torn_tail && i == last_idx;
591        let segment_entries =
592            read_segment_with_cipher_tolerant(path, start_lsn, source, segment_tolerates)?;
593        entries.extend(segment_entries);
594    }
595
596    // Sort entries by LSN to ensure correct ordering across segments.
597    // In a striped WAL architecture, entries can be flushed to different segments
598    // in an order that differs from their LSN assignment order.
599    entries.sort_by_key(|entry| entry.lsn);
600
601    Ok(entries)
602}

604/// Enumerate `*.log` WAL segment files in `wal_dir`, sorted by segment ID.
605///
606/// Shared between the recovery read path ([`read_entries_from_dir_with_cipher`])
607/// and the LSN seeding scan ([`max_lsn_in_dir`]). An unreadable directory
608/// yields an empty list, matching the historical behavior of the read path.
609fn sorted_segment_paths(wal_dir: &Path) -> Vec<(u64, std::path::PathBuf)> {
610    // ⚡ Bolt Optimization: Pre-allocate space for WAL segment paths to prevent
611    // small heap reallocations when reading directories.
612    let mut segments = Vec::with_capacity(16);
613    if let Ok(dir_entries) = std::fs::read_dir(wal_dir) {
614        for entry in dir_entries.flatten() {
615            if let Some(name) = entry.file_name().to_str()
616                && name.ends_with(".log")
617                && let Some(seg_id) = name
618                    .strip_suffix(".log")
619                    .and_then(|s| s.parse::<u64>().ok())
620            {
621                segments.push((seg_id, entry.path()));
622            }
623        }
624    }
625    segments.sort_by_key(|(id, _)| *id);
626    segments
627}

638/// Scan a WAL directory for the maximum LSN present in any segment file.
639///
640/// Standalone, additive helper for Issue #3420: on startup the LSN allocator
641/// must be seeded past every LSN already durable on disk, otherwise a
642/// restarted process re-allocates LSNs that already exist in older segments
643/// (breaking LSN total ordering) and new writes land *below* the manifest
644/// LSN, causing the next startup's differential replay to skip them.
645///
646/// # Torn-tail tolerance
647///
648/// This scan runs inside database **constructors**, so unlike the recovery
649/// read path it must tolerate the data shapes a crash (or another process
650/// sharing the WAL directory) can leave behind: a truncated final entry, a
651/// zeroed preallocated tail, or a torn entry whose header decoded but whose
652/// payload is garbage (e.g. an unknown operation type byte). On encountering
653/// an undecodable entry, the scan stops reading **that segment**, keeps the
654/// maximum LSN decoded from its prefix, logs a warning, and continues with
655/// the remaining segments. A segment that is unreadable from byte 0 (missing
656/// `GWAL` magic, unsupported version, oversized, or encrypted without a
657/// cipher) is skipped entirely with a warning. Only filesystem-level I/O
658/// errors (open/metadata/mmap failures) propagate, exactly as they do from
659/// [`read_segment_with_cipher`].
660///
661/// **Consistency with replay:** the recovery replay reader
662/// (`parse_plaintext_entries`) stops at a truncated or zeroed tail and
663/// hard-errors on any other undecodable entry — either way, replay never
664/// applies anything at or beyond the first undecodable entry of a segment.
665/// Seeding the allocator from each segment's decodable prefix (plus the
666/// index-manifest floor applied by the caller) therefore cannot under-seed
667/// relative to what replay actually applies; tolerating the tail here only
668/// removes constructor failures on data replay would never have applied.
669/// Replay's own error behavior is deliberately unchanged.
670///
671/// # Returns
672///
673/// `Ok(None)` when the directory contains no segments or no decodable
674/// entries; otherwise the maximum LSN across all decodable entries.
675pub fn max_lsn_in_dir(
676    wal_dir: &Path,
677    cipher: Option<&Arc<dyn crate::encryption::cipher::Cipher>>,
678) -> Result<Option<LSN>> {
679    let mut max: Option<LSN> = None;
680    for (_, path) in sorted_segment_paths(wal_dir) {
681        max = max.max(max_lsn_in_segment(&path, cipher)?);
682    }
683    Ok(max)
684}

686/// Scan a WAL directory for the maximum stamped `key_version` across all
687/// segments (Issue #488 version-provisioning).
688///
689/// Reads only segment *headers* — never decrypts a body — so it needs no
690/// cipher and is safe to call before the keyring exists. Returns `None` when no
691/// segment carries a stamped key version: an unencrypted WAL, an empty
692/// directory, or only legacy/pre-rotation segments that predate the
693/// [`WAL_VERSION_ENCRYPTED_KEYVERSIONED`] container. The durable `open()` path
694/// folds this into the provisioned keyring version alongside the index-file
695/// header version. Per-segment I/O errors are swallowed (best-effort, like
696/// [`max_lsn_in_dir`]); a segment whose header does not carry a key version
697/// simply does not contribute.
698#[must_use]
699pub fn max_key_version_in_dir(wal_dir: &Path) -> Option<u32> {
700    let mut max: Option<u32> = None;
701    for (_, path) in sorted_segment_paths(wal_dir) {
702        if let Some(kv) = segment_key_version(&path) {
703            max = Some(max.map_or(kv, |m| m.max(kv)));
704        }
705    }
706    max
707}

709/// Read only a WAL segment header and return its stamped `key_version`, or
710/// `None` for a legacy/plaintext/short/undecodable header. Never reads or
711/// decrypts the segment body.
712fn segment_key_version(path: &Path) -> Option<u32> {
713    use std::io::Read;
714    let mut file = File::open(path).ok()?;
715    let mut header = [0u8; WAL_KEYVERSIONED_HEADER_SIZE];
716    let mut filled = 0usize;
717    while filled < header.len() {
718        match file.read(&mut header[filled..]) {
719            Ok(0) => break,
720            Ok(n) => filled += n,
721            Err(ref e) if e.kind() == std::io::ErrorKind::Interrupted => continue,
722            Err(_) => return None,
723        }
724    }
725    let buffer = &header[..filled];
726    if buffer.len() < WAL_HEADER_SIZE || buffer[0..4] != WAL_MAGIC {
727        return None;
728    }
729    let version = buffer[4];
730    match decode_header_layout(version, buffer) {
731        Ok((_, key_version)) => key_version,
732        Err(_) => None,
733    }
734}

736/// Best-effort maximum-LSN scan of a single segment (see [`max_lsn_in_dir`]).
737///
738/// Never fails on undecodable entry data — returns the maximum LSN of the
739/// segment's decodable prefix instead. Only filesystem-level I/O errors
740/// propagate.
741fn max_lsn_in_segment(
742    path: &Path,
743    cipher: Option<&Arc<dyn crate::encryption::cipher::Cipher>>,
744) -> Result<Option<LSN>> {
745    // Filesystem-level failures propagate exactly like read_segment_with_cipher.
746    let file = match File::open(path) {
747        Ok(f) => f,
748        Err(e) if e.kind() == std::io::ErrorKind::NotFound => return Ok(None),
749        Err(e) => {
750            return Err(StorageError::IoError(format!(
751                "Failed to open WAL segment {:?}: {}",
752                path, e
753            ))
754            .into());
755        }
756    };
757
758    let metadata = file
759        .metadata()
760        .map_err(|e| StorageError::IoError(format!("Failed to get file metadata: {}", e)))?;
761
762    // A zero-byte file can occur if a crash happens immediately after segment
763    // creation; it trivially contributes no LSNs.
764    if metadata.len() == 0 {
765        return Ok(None);
766    }
767
768    if metadata.len() > MAX_SEGMENT_SIZE {
769        log_scan_warning(&format!(
770            "Skipping oversized WAL segment {:?} ({} bytes, max {}) during LSN seeding scan",
771            path,
772            metadata.len(),
773            MAX_SEGMENT_SIZE
774        ));
775        return Ok(None);
776    }
777
778    // Memory-map the file for efficient reading without loading it into memory.
779    // SAFETY: We only read from the memory map, never write. The file is opened
780    // read-only. The mapping is valid for the lifetime of this function and is
781    // automatically unmapped when dropped. We have verified the file size above
782    // to prevent out-of-bounds reads.
783    let mmap = unsafe {
784        memmap2::Mmap::map(&file).map_err(|e| {
785            StorageError::IoError(format!("Failed to memory-map WAL segment: {}", e))
786        })?
787    };
788    let buffer = &mmap[..];
789
790    // Header validation: a segment that is undecodable from byte 0 (garbage
791    // or partially written header, unsupported version) contributes no
792    // decodable LSNs. Replay would apply nothing from it either, so skipping
793    // it with a warning cannot under-seed relative to what replay applies —
794    // and it keeps the constructor usable when e.g. another process is
795    // mid-way through creating a segment in a shared WAL directory.
796    let (version, offset, key_version) = if buffer.len() >= WAL_HEADER_SIZE
797        && buffer[0..4] == WAL_MAGIC
798    {
799        let ver = buffer[4];
800        if !is_supported_segment_version(ver) {
801            log_scan_warning(&format!(
802                "Skipping WAL segment {:?} with unsupported version {} (max {}) during LSN seeding scan",
803                path, ver, WAL_VERSION_KEYVERSIONED_MAX
804            ));
805            return Ok(None);
806        }
807        match decode_header_layout(ver, buffer) {
808            Ok((off, kv)) => (ver, off, kv),
809            Err(_) => {
810                // A keyversioned header truncated before its key_version is a
811                // torn brand-new segment; it contributes no decodable LSNs.
812                log_scan_warning(&format!(
813                    "Skipping WAL segment {:?} with a truncated keyversioned header during LSN seeding scan",
814                    path
815                ));
816                return Ok(None);
817            }
818        }
819    } else {
820        log_scan_warning(&format!(
821            "Skipping WAL segment {:?} without a valid GWAL header during LSN seeding scan",
822            path
823        ));
824        return Ok(None);
825    };
826
827    if is_encrypted_version(version) {
828        // The seeding scan uses the single configured cipher for every segment
829        // (Single/None semantics). A missing/mismatched generation just skips
830        // the segment — the index-manifest LSN floor is the second seed and any
831        // old-generation tail is truncated once the rotation completes.
832        let source: WalCipherSource<'_> = cipher.into();
833        let Some(cipher) = source.resolve(key_version) else {
834            log_scan_warning(&format!(
835                "Skipping encrypted WAL segment {:?} (version {}) during LSN seeding scan: no cipher configured",
836                path, version
837            ));
838            return Ok(None);
839        };
840        Ok(scan_encrypted_max_lsn(
841            buffer, offset, &cipher, path, version,
842        ))
843    } else {
844        Ok(scan_plaintext_max_lsn(buffer, offset, version, path))
845    }
846}

848/// Walk plaintext entry frames, returning the maximum LSN of the decodable
849/// prefix. Mirrors `parse_plaintext_entries`' benign-stop cases (truncated
850/// tail, zeroed preallocated tail) and additionally *stops* — with a warning
851/// instead of an error — at any other undecodable entry (torn tail).
852fn scan_plaintext_max_lsn(
853    buffer: &[u8],
854    mut offset: usize,
855    version: u8,
856    path: &Path,
857) -> Option<LSN> {
858    let mut max: Option<LSN> = None;
859    while offset < buffer.len() {
860        match parse_entry_at(buffer, offset, version) {
861            Ok((entry, bytes_consumed)) => {
862                max = max.max(Some(entry.lsn));
863                offset += bytes_consumed;
864            }
865            Err(e) => {
866                // Same benign-stop cases as parse_plaintext_entries: a partial
867                // entry at EOF or a zeroed preallocated tail.
868                if offset + 24 > buffer.len() || buffer[offset..offset + 24].iter().all(|&b| b == 0)
869                {
870                    break;
871                }
872                // Torn entry (e.g. valid header, garbage payload): stop this
873                // segment, keeping the decodable prefix's max. See the
874                // consistency argument on max_lsn_in_dir.
875                log_scan_warning(&format!(
876                    "Undecodable WAL entry in segment {:?} at offset {} during LSN seeding scan ({}); \
877                     seeding from this segment's decodable prefix",
878                    path, offset, e
879                ));
880                break;
881            }
882        }
883    }
884    max
885}

887/// Walk encrypted (length-prefixed) entry frames, returning the maximum LSN
888/// of the decodable prefix. Mirrors `parse_encrypted_entries`' benign-stop
889/// cases (partial length prefix, zero length, truncated frame) and stops —
890/// with a warning instead of an error — at a frame that fails to decrypt or
891/// parse (torn tail).
892fn scan_encrypted_max_lsn(
893    buffer: &[u8],
894    mut offset: usize,
895    cipher: &Arc<dyn crate::encryption::cipher::Cipher>,
896    path: &Path,
897    container_version: u8,
898) -> Option<LSN> {
899    let entry_version = payload_version(container_version);
900    let mut max: Option<LSN> = None;
901    while offset < buffer.len() {
902        // Partial length prefix at EOF, zero-length end marker, or truncated
903        // frame: same benign stops as parse_encrypted_entries.
904        if offset + 4 > buffer.len() {
905            break;
906        }
907        let len_bytes: [u8; 4] = buffer[offset..offset + 4]
908            .try_into()
909            .expect("slice length verified above");
910        let entry_len = u32::from_le_bytes(len_bytes) as usize;
911        if entry_len == 0 {
912            break;
913        }
914        offset += 4;
915        if offset + entry_len > buffer.len() {
916            break;
917        }
918        let encrypted_entry = &buffer[offset..offset + entry_len];
919        offset += entry_len;
920
921        let decrypted =
922            match crate::encryption::wal_encryption::decrypt_wal_payload(encrypted_entry, cipher) {
923                Ok(d) => d,
924                Err(e) => {
925                    log_scan_warning(&format!(
926                        "Undecryptable WAL entry in segment {:?} during LSN seeding scan ({}); \
927                         seeding from this segment's decodable prefix",
928                        path, e
929                    ));
930                    break;
931                }
932            };
933
934        match parse_entry_at(&decrypted, 0, entry_version) {
935            Ok((entry, _bytes_consumed)) => max = max.max(Some(entry.lsn)),
936            Err(e) => {
937                log_scan_warning(&format!(
938                    "Undecodable decrypted WAL entry in segment {:?} during LSN seeding scan ({}); \
939                     seeding from this segment's decodable prefix",
940                    path, e
941                ));
942                break;
943            }
944        }
945    }
946    max
947}

1073    }

1075    // Handle empty files explicitly to avoid mmap failure on some platforms (e.g. macOS/Windows)
1076    // A zero-byte file can occur if a crash happens immediately after segment creation.
1077    if metadata.len() == 0 {
1078        return Ok(Vec::new());
1079    }
1080
1081    // Memory-map the file for efficient reading without loading entire file into memory.
1082    // SAFETY: We only read from the memory map, never write. The file is opened read-only.
1083    // The mapping is valid for the lifetime of this function and is automatically unmapped
1084    // when dropped. We have verified the file size above to prevent out-of-bounds reads.
1085    let mmap = unsafe {
1086        memmap2::Mmap::map(&file).map_err(|e| {
1087            StorageError::IoError(format!("Failed to memory-map WAL segment: {}", e))
1088        })?
1089    };
1090
1091    // Use the memory-mapped region as a byte slice
1092    let buffer = &mmap[..];
1093
1094    // ⚡ Bolt Optimization: Pre-allocate vector based on buffer size.
1095    // Assuming an average WAL entry is ~128 bytes, this prevents numerous
1096    // heap reallocations when reading large segments.
1097    let capacity_hint = (buffer.len() / 128).max(1);
1098    let mut entries = Vec::with_capacity(capacity_hint);
1099
1100    // Detect WAL format version and header layout (Issue #3617: a v16
1101    // KEYVERSIONED segment carries a 9-byte header with a trailing key_version;
1102    // all legacy families use the 5-byte header).
1103    let (version, mut offset, key_version) =
1104        if buffer.len() >= WAL_HEADER_SIZE && buffer[0..4] == WAL_MAGIC {
1105            // Version 1+ format: has magic header
1106            let ver = buffer[4];
1107            if !is_supported_segment_version(ver) {
1108                return Err(StorageError::CorruptedData(format!(
1109                    "Unsupported WAL version: {} (max supported: {})",
1110                    ver, WAL_VERSION_KEYVERSIONED_MAX
1111                ))
1112                .into());
1113            }
1114            let (off, kv) = match decode_header_layout(ver, buffer) {
1115                Ok(layout) => layout,
1116                // A keyversioned (v16) header truncated mid-`key_version` (5..9
1117                // bytes present) on the FINAL segment, under torn-tail tolerance,
1118                // is a crash-torn empty tail — not a hard error. This mirrors the
1119                // #3433 torn-tail contract already applied to a torn trailing
1120                // ENTRY: without the full 9-byte header there are no decodable
1121                // frames, so keep nothing and stop cleanly rather than aborting
1122                // recovery on the whole segment.
1123                Err(e) if tolerate_torn_tail => {
1124                    log_torn_tail_warning(path, WAL_HEADER_SIZE, &e);
1125                    return Ok(Vec::new());
1126                }
1127                Err(e) => return Err(e),
1128            };
1129            (ver, off, kv)
1130        } else if !buffer.is_empty() {
1131            // Invalid format: no magic header
1132            return Err(StorageError::CorruptedData(
1133                "Invalid WAL segment: missing GWAL magic header".to_string(),
1134            )
1135            .into());
1136        } else {
1137            return Ok(Vec::new()); // Empty segment
1138        };
1139
1140    // Encrypted segments require a WAL DEK. Resolve the right generation for
1141    // this segment's key_version up front (legacy segments -> pre-rotation
1142    // generation); a missing cipher/generation is a loud error, never silent
1143    // wrong data. Only the integer version numbers are named — never key bytes.
1144    let resolved_cipher = if is_encrypted_version(version) {
1145        match source.resolve(key_version) {
1146            Some(c) => Some(c),
1147            None if source.is_present() => {
1148                return Err(StorageError::Encryption(format!(
1149                    "Cannot read encrypted WAL segment (version {}, key_version {:?}): \
1150                     no matching WAL DEK generation available",
1151                    version, key_version
1152                ))
1153                .into());
1154            }
1155            None => {
1156                return Err(StorageError::Encryption(format!(
1157                    "Cannot read encrypted WAL segment (version {}) without a cipher",
1158                    version
1159                ))
1160                .into());
1161            }
1162        }
1163    } else {
1164        None
1165    };
1166
1167    // Dispatch to the appropriate parsing loop based on version.
1168    if is_encrypted_version(version) {
1169        // Encrypted: length-prefixed encrypted entries.
1170        let cipher = resolved_cipher
1171            .as_ref()
1172            .expect("cipher presence checked above");
1173        parse_encrypted_entries(
1174            buffer,
1175            &mut offset,
1176            start_lsn,
1177            cipher,
1178            path,
1179            &mut entries,
1180            version,
1181            tolerate_torn_tail,
1182        )?;
1183    } else {
1184        // Plaintext (1/3/5/7): plaintext entries.
1185        parse_plaintext_entries(
1186            buffer,
1187            &mut offset,
1188            version,
1189            start_lsn,
1190            path,
1191            &mut entries,
1192            tolerate_torn_tail,
1193        )?;
1194    }
1195
1196    Ok(entries)
1197}

1199/// Log a WARNING that replay stopped at a crash-torn trailing entry, under both
1200/// logging configurations (Issue #3433). Carries the segment path, byte offset,
1201/// and the underlying parse/decrypt error so operators can audit exactly where
1202/// the log tail was truncated.
1203fn log_torn_tail_warning(path: &Path, offset: usize, err: &Error) {
1204    let msg = format!(
1205        "Crash-torn trailing WAL entry in final segment {:?} at byte offset {}: {}; \
1206         stopping replay here and keeping the decodable prefix (torn entries were never \
1207         acknowledged, so discarding them is correct)",
1208        path, offset, err
1209    );
1210    #[cfg(feature = "observability")]
1211    tracing::warn!("{}", msg);
1212    #[cfg(not(feature = "observability"))]
1213    eprintln!("WARNING: {}", msg);

1216/// Parse plaintext (versions 1/3/5/7) entries from a WAL segment buffer.
1217///
1218/// See [`read_segment_with_cipher_tolerant`] for the meaning of
1219/// `tolerate_torn_tail`.
1220fn parse_plaintext_entries(
1221    buffer: &[u8],
1222    offset: &mut usize,
1223    version: u8,
1224    start_lsn: LSN,
1225    path: &Path,
1226    entries: &mut Vec<WalEntry>,
1227    tolerate_torn_tail: bool,
1228) -> Result<()> {
1229    // LSN of the last entry we successfully decoded (regardless of the
1230    // `start_lsn` push filter). A genuine continuation entry after an
1231    // undecodable one has a strictly higher LSN; this guards the forward probe
1232    // (below) against a ~2^-32 CRC false positive from mis-aligned bytes.
1233    let mut last_parsed_lsn: Option<LSN> = None;
1234
1235    while *offset < buffer.len() {
1236        match parse_entry_at(buffer, *offset, version) {
1237            Ok((entry, bytes_consumed)) => {
1238                last_parsed_lsn = Some(entry.lsn);
1239                if entry.lsn >= start_lsn {
1240                    entries.push(entry);
1241                }
1242                *offset += bytes_consumed;
1243            }
1244            Err(e) => {
1245                // Distinguish between expected EOF truncation vs. unexpected corruption
1246                if *offset + 24 > buffer.len() {
1247                    // Partial header (torn write, < 24 bytes left): the entry
1248                    // cannot even form a header, so nothing valid can follow —
1249                    // this is a genuine torn tail. An all-zero remainder is
1250                    // benign pre-allocation padding and is ALWAYS treated as
1251                    // end-of-log (hard-erroring on it would brick normal
1252                    // startup). A NONZERO partial header is a torn append:
1253                    // tolerated under the flag, fail-stop when opted out
1254                    // (Issue #3433 / PR #3461 config fix — this branch used to
1255                    // `break` unconditionally, ignoring `tolerate_torn_tail`).
1256                    let remainder = &buffer[*offset..];
1257                    if remainder.iter().all(|&b| b == 0) {
1258                        #[cfg(feature = "observability")]
1259                        tracing::debug!(
1260                            "Zeroed partial region at end of WAL segment {:?} (offset {}/{}), stopping read",
1261                            path,
1262                            offset,
1263                            buffer.len()
1264                        );
1265                        break;
1266                    }
1267                    if tolerate_torn_tail {
1268                        log_torn_tail_warning(path, *offset, &e);
1269                        break;
1270                    }
1271                    return Err(e);
1272                } else {
1273                    let header_slice = &buffer[*offset..*offset + 24];
1274                    if header_slice.iter().all(|&b| b == 0) {
1275                        #[cfg(feature = "observability")]
1276                        tracing::debug!(
1277                            "Zeroed region at end of WAL segment {:?} (offset {}/{}), stopping read",
1278                            path,
1279                            offset,
1280                            buffer.len()
1281                        );
1282                        break;
1283                    }
1284
1285                    // An undecodable full entry (Issue #3433 / PR #3461
1286                    // corruption-safety fix). Plaintext entries carry NO
1287                    // per-entry length prefix, so we cannot resync by a length
1288                    // field — but we CAN still tell a crash-torn tail apart
1289                    // from mid-log corruption by scanning forward for a real
1290                    // continuation entry (`plaintext_valid_entry_follows`):
1291                    //
1292                    // * A valid entry with a HIGHER LSN survives after this one
1293                    //   => acknowledged committed data lies past the corruption.
1294                    //   This is mid-log damage, NOT a torn tail, and MUST
1295                    //   hard-error even with `tolerate_torn_tail = true` — the
1296                    //   tolerant default must never silently drop the bytes of a
1297                    //   real transaction (which, plaintext being length-prefix
1298                    //   free, could be up to a whole 64 MB segment).
1299                    // * Nothing valid follows (scan reaches EOF) => a genuine
1300                    //   crash-torn tail (zeroed/garbage op-type, mid-field
1301                    //   truncation, or a checksum mismatch on a half-written
1302                    //   payload). The torn entry was never acknowledged, so we
1303                    //   keep the decodable prefix and stop — but only under the
1304                    //   flag (a non-final segment or `tolerate_torn_tail = false`
1305                    //   still hard-errors).
1306                    //
1307                    // This mirrors the encrypted path's `encrypted_valid_frame_follows`
1308                    // lookahead, closing the plaintext data-loss asymmetry.
1309                    if !plaintext_valid_entry_follows(buffer, *offset, version, last_parsed_lsn)
1310                        && tolerate_torn_tail
1311                    {
1312                        log_torn_tail_warning(path, *offset, &e);
1313                        break;
1314                    }
1315
1316                    #[cfg(feature = "observability")]
1317                    tracing::error!(
1318                        "Failed to parse WAL entry in segment {:?} at offset {}: {}",
1319                        path,
1320                        offset,
1321                        e
1322                    );
1323                    #[cfg(not(feature = "observability"))]
1324                    {
1325                        eprintln!(
1326                            "CRITICAL: Failed to parse WAL entry in segment {:?} at offset {}: {}",
1327                            path, offset, e
1328                        );
1329                        eprintln!("Header slice: {:?}", header_slice);
1330                    }
1331                    return Err(e);
1332                }
1333            }
1334        }
1335    }
1336    Ok(())
1337}

1339/// Scanning forward from `start` (byte by byte, because plaintext WAL entries
1340/// carry no per-entry length prefix), does any position decode via
1341/// [`parse_entry_at`] into a valid, CRC-checked entry whose LSN is strictly
1342/// greater than `last_parsed_lsn`? (Issue #3433 / PR #3461 corruption-safety.)
1343///
1344/// This is the plaintext analogue of [`encrypted_valid_frame_follows`]. A
1345/// `true` answer means a real committed entry survives PAST an undecodable one
1346/// — i.e. mid-log corruption, not a crash-torn tail — so replay must hard-error
1347/// regardless of `tolerate_torn_tail`. A `false` answer (the scan reaches
1348/// end-of-buffer with nothing valid after) means a genuine torn tail, and the
1349/// caller applies the flag.
1350///
1351/// The `> last_parsed_lsn` guard rejects a ~2^-32 CRC false positive from
1352/// mis-aligned bytes: a genuine continuation always has a strictly higher LSN
1353/// than the last entry we decoded (WAL LSNs increase monotonically). When
1354/// nothing has been decoded yet (`None`), any valid following entry counts —
1355/// a corrupt first entry with a valid entry after it is still mid-log damage.
1356///
1357/// The scan runs only on the error path during recovery (rare) and is bounded
1358/// by the remaining segment bytes.
1359fn plaintext_valid_entry_follows(
1360    buffer: &[u8],
1361    start: usize,
1362    version: u8,
1363    last_parsed_lsn: Option<LSN>,
1364) -> bool {
1365    // `start` itself already failed to parse; begin at the next byte.
1366    let mut scan = start + 1;
1367    while scan + 24 <= buffer.len() {
1368        if let Ok((entry, _)) = parse_entry_at(buffer, scan, version) {
1369            match last_parsed_lsn {
1370                Some(last) if entry.lsn > last => return true,
1371                None => return true,
1372                _ => {}
1373            }
1374        }
1375        scan += 1;
1376    }
1377    false
1378}

1380/// Parse encrypted (versions 2/4/6/8) entries from a WAL segment buffer.
1381///
1382/// Each entry is stored as `[4-byte LE length][encrypted entry bytes]`.
1383/// The encrypted entry bytes are decrypted using the provided cipher,
1384/// then parsed as a normal WAL entry using the payload version implied by
1385/// `container_version` (see [`payload_version`]).
1386///
1387/// See [`read_segment_with_cipher_tolerant`] for the meaning of
1388/// `tolerate_torn_tail`.
1389#[allow(clippy::too_many_arguments)]
1390fn parse_encrypted_entries(
1391    buffer: &[u8],
1392    offset: &mut usize,
1393    start_lsn: LSN,
1394    cipher: &Arc<dyn crate::encryption::cipher::Cipher>,
1395    path: &Path,
1396    entries: &mut Vec<WalEntry>,
1397    container_version: u8,
1398    tolerate_torn_tail: bool,
1399) -> Result<()> {
1400    let entry_version = payload_version(container_version);
1401    while *offset < buffer.len() {
1402        // Byte offset of this frame's length prefix, for torn-tail warnings.
1403        let frame_start = *offset;
1404        // Need at least 4 bytes for the length prefix
1405        if *offset + 4 > buffer.len() {
1406            // Partial length prefix at EOF -- a torn write. An all-zero
1407            // remainder is benign pre-allocation padding (always end-of-log);
1408            // a nonzero partial prefix is a torn tail: tolerated under the flag,
1409            // fail-stop when opted out (Issue #3433 / PR #3461 config fix —
1410            // this used to `break` unconditionally, ignoring the flag).
1411            let remainder = &buffer[*offset..];
1412            if remainder.iter().all(|&b| b == 0) {
1413                break;
1414            }
1415            let err = Error::Storage(StorageError::CorruptedData(format!(
1416                "Partial encrypted length prefix at end of WAL segment {:?} (offset {}/{})",
1417                path,
1418                *offset,
1419                buffer.len()
1420            )));
1421            if tolerate_torn_tail {
1422                log_torn_tail_warning(path, frame_start, &err);
1423                break;
1424            }
1425            return Err(err);
1426        }
1427
1428        // Check for zeroed length prefix (indicates end of data in pre-allocated files)
1429        let len_bytes: [u8; 4] = buffer[*offset..*offset + 4]
1430            .try_into()
1431            .expect("slice length verified above");
1432        let entry_len = u32::from_le_bytes(len_bytes) as usize;
1433
1434        if entry_len == 0 {
1435            // Zero-length entry marks end of valid data (pre-allocation
1436            // padding). Always benign — never gated on the flag.
1437            break;
1438        }
1439
1440        *offset += 4;
1441
1442        // Validate entry length
1443        if *offset + entry_len > buffer.len() {
1444            // Truncated encrypted entry at EOF -- a torn write. A length-prefix
1445            // that points past the end of the buffer means the frame body was
1446            // never fully written, so nothing valid can follow: a genuine torn
1447            // tail. Tolerated under the flag, fail-stop when opted out
1448            // (Issue #3433 / PR #3461 config fix — used to `break`
1449            // unconditionally, ignoring the flag).
1450            let err = Error::Storage(StorageError::CorruptedData(format!(
1451                "Truncated encrypted entry at end of WAL segment {:?} (offset {}, entry_len {}, buf_len {})",
1452                path,
1453                *offset,
1454                entry_len,
1455                buffer.len()
1456            )));
1457            if tolerate_torn_tail {
1458                log_torn_tail_warning(path, frame_start, &err);
1459                break;
1460            }
1461            return Err(err);
1462        }
1463
1464        let encrypted_entry = &buffer[*offset..*offset + entry_len];
1465        *offset += entry_len;
1466
1467        // Decrypt the entry. A crash-torn tail can leave a length-complete but
1468        // undecryptable final frame (Issue #3433). Encrypted frames ARE
1469        // length-prefixed, so unlike plaintext we can — and MUST — distinguish a
1470        // torn tail from mid-log corruption: tolerate only when NO valid frame
1471        // follows this one; if a later frame still decrypts and parses, this is
1472        // resyncable mid-log damage and must hard-error even in the final
1473        // segment.
1474        let decrypted =
1475            match crate::encryption::wal_encryption::decrypt_wal_payload(encrypted_entry, cipher) {
1476                Ok(d) => d,
1477                Err(e) => {
1478                    let err = Error::Storage(StorageError::Encryption(format!(
1479                        "Failed to decrypt WAL entry in segment {:?}: {}",
1480                        path, e
1481                    )));
1482                    if tolerate_torn_tail
1483                        && !encrypted_valid_frame_follows(buffer, *offset, cipher, entry_version)
1484                    {
1485                        log_torn_tail_warning(path, frame_start, &err);
1486                        break;
1487                    }
1488                    return Err(err);
1489                }
1490            };
1491
1492        // Parse the decrypted bytes as a normal entry, using the payload
1493        // version implied by the container version (plaintext-equivalent).
1494        match parse_entry_at(&decrypted, 0, entry_version) {
1495            Ok((entry, _bytes_consumed)) => {
1496                if entry.lsn >= start_lsn {
1497                    entries.push(entry);
1498                }
1499            }
1500            Err(e) => {
1501                // Same crash-torn-tail policy as the decrypt branch above:
1502                // tolerate a length-complete-but-undecodable final frame only
1503                // when no valid frame follows it.
1504                if tolerate_torn_tail
1505                    && !encrypted_valid_frame_follows(buffer, *offset, cipher, entry_version)
1506                {
1507                    log_torn_tail_warning(path, frame_start, &e);
1508                    break;
1509                }
1510                #[cfg(feature = "observability")]
1511                tracing::error!(
1512                    "Failed to parse decrypted WAL entry in segment {:?}: {}",
1513                    path,
1514                    e
1515                );
1516                #[cfg(not(feature = "observability"))]
1517                eprintln!(
1518                    "CRITICAL: Failed to parse decrypted WAL entry in segment {:?}: {}",
1519                    path, e
1520                );
1521                return Err(e);
1522            }
1523        }
1524    }
1525    Ok(())
1526}

1528/// Does any length-prefixed encrypted frame at or after `offset` still decrypt
1529/// AND parse into a valid WAL entry? (Issue #3433)
1530///
1531/// Used by [`parse_encrypted_entries`] to distinguish a crash-torn tail from
1532/// resyncable mid-log corruption: because encrypted frames are length-prefixed,
1533/// a failed frame that is FOLLOWED BY a recoverable frame is real damage (and
1534/// must hard-error), whereas a failed frame with nothing decodable after it is
1535/// the torn tail (and may be dropped). Partial/zero-length trailing frames end
1536/// the scan without counting as "valid following".
1537///
1538/// KNOWN LIMITATION (defensive follow-up, not fixed here): the 4-byte little-
1539/// endian length prefix that frames each ciphertext lives OUTSIDE the AEAD
1540/// envelope — it is neither encrypted nor authenticated. A mid-stream corrupted
1541/// or tampered length prefix can therefore point the scan at the wrong offset
1542/// and desync this lookahead (skip a real following frame, or realign onto
1543/// garbage), weakening the torn-tail-vs-mid-log-corruption discrimination for
1544/// encrypted segments specifically. Hardening this needs a WAL format change
1545/// (bind the length into the frame's AAD, or length-prefix-inside-envelope) and
1546/// is tracked separately; do NOT rely on this probe as an integrity guarantee
1547/// against an adversary who can edit length prefixes.
1548fn encrypted_valid_frame_follows(
1549    buffer: &[u8],
1550    mut offset: usize,
1551    cipher: &Arc<dyn crate::encryption::cipher::Cipher>,
1552    entry_version: u8,
1553) -> bool {
1554    while offset < buffer.len() {
1555        if offset + 4 > buffer.len() {
1556            return false;
1557        }
1558        let entry_len = u32::from_le_bytes(
1559            buffer[offset..offset + 4]
1560                .try_into()
1561                .expect("slice length verified above"),
1562        ) as usize;
1563        if entry_len == 0 {
1564            return false;
1565        }
1566        offset += 4;
1567        if offset + entry_len > buffer.len() {
1568            return false;
1569        }
1570        let frame = &buffer[offset..offset + entry_len];
1571        offset += entry_len;
1572        if let Ok(decrypted) = crate::encryption::wal_encryption::decrypt_wal_payload(frame, cipher)
1573            && parse_entry_at(&decrypted, 0, entry_version).is_ok()
1574        {
1575            return true;
1576        }
1577        // Otherwise keep scanning: a single bad frame followed by more bad
1578        // frames is still a tail unless SOMETHING valid appears later.
1579    }
1580    false
1581}

1583/// Advance `offset` by `n` bytes with overflow protection.
1584#[inline]
1585fn advance(offset: &mut usize, n: usize) -> Result<()> {
1586    *offset = offset.checked_add(n).ok_or_else(|| {
1587        Error::Storage(StorageError::CorruptedData(
1588            "WAL offset overflow".to_string(),
1589        ))
1590    })?;
1591    Ok(())
1592}

1594/// Verify at least `n` bytes are available from `offset` in `buffer`.
1595///
1596/// Returns an overflow error if `offset + n` would overflow, or a `CorruptedData`
1597/// error with `context` in the message if the buffer is too short.
1598#[inline]
1599fn require_bytes(buffer: &[u8], offset: usize, n: usize, context: &str) -> Result<()> {
1600    let end = offset.checked_add(n).ok_or_else(|| {
1601        Error::Storage(StorageError::CorruptedData(
1602            "WAL offset overflow".to_string(),
1603        ))
1604    })?;
1605    if end > buffer.len() {
1606        return Err(StorageError::CorruptedData(format!(
1607            "Insufficient buffer size for {}",
1608            context
1609        ))
1610        .into());
1611    }
1612    Ok(())
1613}

1615/// Read an optional `String` field: `[1-byte presence][4-byte LE len][UTF-8 bytes]`.
1616///
1617/// The length and bytes are only present when the presence byte is nonzero.
1618fn read_opt_string(buffer: &[u8], offset: &mut usize, context: &str) -> Result<Option<String>> {
1619    require_bytes(buffer, *offset, 1, context)?;
1620    let present = buffer[*offset];
1621    advance(offset, 1)?;
1622    if present == 0 {
1623        return Ok(None);
1624    }
1625    require_bytes(buffer, *offset, 4, context)?;
1626    let len = u32::from_le_bytes(buffer[*offset..*offset + 4].try_into().unwrap()) as usize;
1627    advance(offset, 4)?;
1628    require_bytes(buffer, *offset, len, context)?;
1629    let s = std::str::from_utf8(&buffer[*offset..*offset + len])
1630        .map_err(|e| StorageError::CorruptedData(format!("Invalid UTF-8 in {}: {}", context, e)))?
1631        .to_string();
1632    advance(offset, len)?;
1633    Ok(Some(s))
1634}

1650/// Read an optional [`Provenance`] bundle written by `serialize_provenance_into`.
1651///
1652/// Segments below [`WAL_VERSION_PROVENANCE`] never contain these bytes at
1653/// all; for those, this returns `Ok(None)` without touching `offset`.
1654fn read_provenance(buffer: &[u8], offset: &mut usize, version: u8) -> Result<Option<Provenance>> {
1655    if version < WAL_VERSION_PROVENANCE {
1656        return Ok(None);
1657    }
1658    require_bytes(buffer, *offset, 1, "provenance presence")?;
1659    let present = buffer[*offset];
1660    advance(offset, 1)?;
1661    if present == 0 {
1662        return Ok(None);
1663    }
1664
1665    let source = read_opt_string(buffer, offset, "provenance.source")?;
1666    let confidence = read_opt_f64(buffer, offset, "provenance.confidence")?;
1667    let note = read_opt_string(buffer, offset, "provenance.note")?;
1668    let correlation_id = read_opt_string(buffer, offset, "provenance.correlation_id")?;
1669    // The authenticated-principal field (Issue #3350) only exists on
1670    // segments at or above WAL_VERSION_PROVENANCE_PRINCIPAL; older
1671    // provenance-carrying segments end the bundle at correlation_id.
1672    let principal = if version >= WAL_VERSION_PROVENANCE_PRINCIPAL {
1673        read_opt_string(buffer, offset, "provenance.principal")?
1674    } else {
1675        None
1676    };
1677
1678    let mut builder = Provenance::builder();
1679    if let Some(source) = source {
1680        builder = builder.source(source);
1681    }
1682    if let Some(confidence) = confidence {
1683        builder = builder.confidence(confidence);
1684    }
1685    if let Some(note) = note {
1686        builder = builder.note(note);
1687    }
1688    if let Some(correlation_id) = correlation_id {
1689        builder = builder.correlation_id(correlation_id);
1690    }
1691    if let Some(principal) = principal {
1692        builder = builder.principal(principal);
1693    }
1694    let provenance = builder.build().map_err(|e| {
1695        StorageError::CorruptedData(format!("Invalid provenance in WAL entry: {}", e))
1696    })?;
1697    Ok(Some(provenance))
1698}

1700/// Read a label from `buffer` at `offset`, advancing `offset` past it.
1701///
1702/// For v13+ segments ([`carries_string_labels`], Issue #3506) the label is a
1703/// length-prefixed UTF-8 string (`[len: u32-LE][utf8 bytes]`) which is
1704/// re-interned into the process-global interner on read, so it resolves to the
1705/// correct string under ANY interner layout (byte-identical to the property-key
1706/// codec). For ≤v12 segments the label is a raw 4-byte [`InternedString`] id
1707/// wrapped via [`InternedString::from_raw`] — correct only when the replaying
1708/// process reproduces the writer's interner layout (the pre-#3506 behavior,
1709/// preserved for backward compatibility).
1710#[inline]
1711fn read_label(
1712    buffer: &[u8],
1713    offset: &mut usize,
1714    version: u8,
1715    context: &str,
1716) -> Result<crate::core::interning::InternedString> {
1717    if carries_string_labels(version) {
1718        require_bytes(buffer, *offset, 4, context)?;
1719        let len = u32::from_le_bytes(buffer[*offset..*offset + 4].try_into().unwrap()) as usize;
1720        advance(offset, 4)?;
1721        require_bytes(buffer, *offset, len, context)?;
1722        let s = std::str::from_utf8(&buffer[*offset..*offset + len]).map_err(|e| {
1723            StorageError::CorruptedData(format!("Invalid UTF-8 in WAL label ({context}): {e}"))
1724        })?;
1725        let interned = crate::core::interning::GLOBAL_INTERNER.intern(s)?;
1726        advance(offset, len)?;
1727        Ok(interned)
1728    } else {
1729        require_bytes(buffer, *offset, 4, context)?;
1730        let label_id = u32::from_le_bytes(buffer[*offset..*offset + 4].try_into().unwrap());
1731        advance(offset, 4)?;
1732        Ok(crate::core::interning::InternedString::from_raw(label_id))
1733    }
1734}

2068/// Parse a single WAL entry from a buffer at the specified offset.
2069///
2070/// This function extracts the parsing logic that was previously duplicated
2071/// in multiple places (issue #218). It handles all WAL operation types and
2072/// returns both the parsed entry and the number of bytes consumed.
2073///
2074/// # Arguments
2075///
2076/// * `buffer` - The buffer containing serialized WAL data
2077/// * `offset` - The offset in the buffer to start parsing from
2078/// * `version` - The WAL format version
2079///
2080/// # Returns
2081///
2082/// A tuple of (WalEntry, bytes_consumed) on success, or an error if:
2083/// - The buffer is too small to contain a valid entry
2084/// - The operation type is unknown
2085/// - The data is corrupted or truncated
2086///
2087/// # Example
2088///
2089/// ```ignore
2090/// let (entry, bytes_consumed) = parse_entry_at(&buffer, 0, WAL_VERSION)?;
2091/// let next_offset = offset + bytes_consumed;
2092/// ```
2093pub(crate) fn parse_entry_at(
2094    buffer: &[u8],
2095    offset: usize,
2096    version: u8,
2097) -> Result<(WalEntry, usize)> {
2098    let start_offset = offset;
2099    let mut cur = offset;
2100
2101    // Need at least 24 bytes for LSN (8) + HybridTimestamp (12) + checksum (4)
2102    require_bytes(buffer, cur, 24, "WAL entry header")?;
2103
2104    let lsn = LSN(u64::from_le_bytes(
2105        buffer[cur..cur + 8].try_into().unwrap(), // Safe: require_bytes verified 24 bytes
2106    ));
2107    advance(&mut cur, 8)?;
2108
2109    let (timestamp, _) = HybridTimestamp::deserialize(&buffer[cur..]).map_err(|e| {
2110        StorageError::CorruptedData(format!("Failed to deserialize timestamp: {}", e))
2111    })?;
2112    advance(&mut cur, 12)?;
2113
2114    let checksum = u32::from_le_bytes(
2115        buffer[cur..cur + 4].try_into().unwrap(), // Safe: require_bytes verified 24 bytes
2116    );
2117    advance(&mut cur, 4)?;
2118
2119    if cur >= buffer.len() {
2120        return Err(StorageError::CorruptedData(
2121            "Insufficient buffer size for operation type".to_string(),
2122        )
2123        .into());
2124    }
2125    let op_type = buffer[cur];
2126    advance(&mut cur, 1)?;
2127
2128    let operation = match op_type {
2129        OP_CREATE_NODE => parse_create_node_op(buffer, &mut cur, version, timestamp)?,
2130        OP_CREATE_EDGE => parse_create_edge_op(buffer, &mut cur, version, timestamp)?,
2131        OP_UPDATE_NODE => parse_update_node_op(buffer, &mut cur, version, timestamp)?,
2132        OP_UPDATE_EDGE => parse_update_edge_op(buffer, &mut cur, version, timestamp)?,
2133        OP_DELETE_NODE => parse_delete_node_op(buffer, &mut cur, version, timestamp)?,
2134        OP_DELETE_EDGE => parse_delete_edge_op(buffer, &mut cur, version, timestamp)?,
2135        OP_RETRACT_NODE => parse_retract_node_op(buffer, &mut cur, version)?,
2136        OP_RETRACT_EDGE => parse_retract_edge_op(buffer, &mut cur, version)?,
2137        OP_CHECKPOINT => parse_checkpoint_op(buffer, &mut cur)?,
2138        OP_DECLARE_UNIQUE_CONSTRAINT => {
2139            let label = read_label(buffer, &mut cur, version, "DeclareUniqueConstraint.label")?;
2140            let property = read_label(
2141                buffer,
2142                &mut cur,
2143                version,
2144                "DeclareUniqueConstraint.property",
2145            )?;
2146            WalOperation::DeclareUniqueConstraint { label, property }
2147        }
2148        OP_DROP_UNIQUE_CONSTRAINT => {
2149            let label = read_label(buffer, &mut cur, version, "DropUniqueConstraint.label")?;
2150            let property = read_label(buffer, &mut cur, version, "DropUniqueConstraint.property")?;
2151            WalOperation::DropUniqueConstraint { label, property }
2152        }
2153        OP_BEGIN_TX => parse_begin_tx_op(buffer, &mut cur)?,
2154        OP_COMMIT_TX => parse_commit_tx_op(buffer, &mut cur)?,
2155        _ => {
2156            return Err(StorageError::CorruptedData(format!(
2157                "Unknown WAL operation type: {}",
2158                op_type
2159            ))
2160            .into());
2161        }
2162    };
2163
2164    // Verify checksum to ensure data integrity (critical for WAL correctness)
2165    let mut hasher = crc32fast::Hasher::new();
2166    // Hash LSN (8 bytes) + timestamp (12 bytes) = bytes 0..20
2167    hasher.update(&buffer[start_offset..start_offset + 20]);
2168    // Hash operation data (from after checksum field to end of entry)
2169    hasher.update(&buffer[start_offset + 24..cur]);
2170    let computed_checksum = hasher.finalize();
2171
2172    if checksum != computed_checksum {
2173        return Err(StorageError::CorruptedData(format!(
2174            "WAL entry checksum mismatch for LSN {}: expected {:#x}, got {:#x}. Entry is corrupted.",
2175            lsn.0, checksum, computed_checksum
2176        ))
2177        .into());
2178    }
2179
2180    let entry = WalEntry {
2181        lsn,
2182        timestamp,
2183        operation,
2184        checksum,
2185        // Segments at or above WAL_VERSION_TX_FRAMING carry transaction
2186        // framing markers; `version` here is the plaintext/payload version
2187        // (encrypted container versions are mapped via `payload_version`
2188        // before reaching this function), so the comparison is uniform.
2189        framed: is_framed_version(version),
2190    };
2191    let bytes_consumed = cur - start_offset;
2192    Ok((entry, bytes_consumed))
2193}
