1//! Write-Ahead Log (WAL) implementation for crash recovery and durability.
2//!
3//! The WAL provides:
4//! - Sequential logging of all mutations
5//! - Crash recovery by replaying operations
6//! - Point-in-time recovery capabilities
7//! - Configurable durability modes for performance tuning
8//!
9//! # Architecture
10//!
11//! AletheiaDB uses a **Concurrent WAL with Striped Lock-Free Ring Buffers** for
12//! high-throughput write operations while maintaining ACID compliance.
13//!
14//! ```text
15//!                     ┌─────────────────────┐
16//!                     │    LSN Allocator    │
17//!                     │  AtomicU64::fetch_add
18//!                     └──────────┬──────────┘
19//!                                │
20//!        ┌───────────────────────┼───────────────────────┐
21//!        ▼                       ▼                       ▼
22//! ┌─────────────┐         ┌─────────────┐         ┌─────────────┐
23//! │   Stripe 0  │         │   Stripe 1  │         │  Stripe N   │
24//! │ Ring Buffer │         │ Ring Buffer │         │ Ring Buffer │
25//! │ (Lock-free) │         │ (Lock-free) │         │ (Lock-free) │
26//! └──────┬──────┘         └──────┬──────┘         └──────┬──────┘
27//!        └───────────────────────┼───────────────────────┘
28//!                                ▼
29//!                     ┌─────────────────────┐
30//!                     │  Flush Coordinator  │
31//!                     │  - Sorts by LSN     │
32//!                     │  - Writes segment   │
33//!                     └─────────────────────┘
34//! ```
35//!
36//! # Key Design Principles
37//!
38//! 1. **Lock-free append path**: Multiple threads can append concurrently without mutex contention
39//! 2. **Global LSN ordering**: Single atomic counter ensures total ordering of all operations
40//! 3. **Sorted flush**: Entries are sorted by LSN before writing to disk
41//! 4. **ACID preserved**: Synchronous and GroupCommit modes remain fully ACID compliant
42//!
43//! # Durability Modes
44//!
45//! | Mode | Latency | Throughput | ACID |
46//! |------|---------|------------|------|
47//! | Synchronous | ~1.5ms | ~600/sec | ✅ Full |
48//! | GroupCommit | ~10-50ms | ~100K+/sec | ✅ Full |
49//! | Async | <100ns | ~500K+/sec | ❌ Eventual |
50//!
51//! See [`DurabilityMode`] for details.
52//!
53//! # Usage
54//!
55//! ## Single Operations
56//!
57//! ```ignore
58//! use aletheiadb::storage::wal::concurrent_system::{ConcurrentWalSystem, ConcurrentWalSystemConfig};
59//!
60//! let config = ConcurrentWalSystemConfig::new("data/wal");
61//! let wal = ConcurrentWalSystem::new(config)?;
62//!
63//! // Async append (returns immediately)
64//! let lsn = wal.append_async(operation)?;
65//!
66//! // Commit with configured durability
67//! wal.commit()?;
68//!
69//! // Shutdown gracefully
70//! wal.shutdown();
71//! ```
72//!
73//! ## Batch Operations (High-Throughput)
74//!
75//! For high-throughput workloads with multiple operations, use `append_batch()` for
76//! significant performance improvements:
77//!
78//! ```ignore
79//! use aletheiadb::storage::wal::{WalOperation, ConcurrentWalSystem};
80//!
81//! // Create multiple operations (e.g., from a transaction)
82//! let operations = vec![
83//!     WalOperation::CreateNode { /* ... */ },
84//!     WalOperation::CreateEdge { /* ... */ },
85//!     WalOperation::UpdateNode { /* ... */ },
86//! ];
87//!
88//! // Batch append - optimizes LSN allocation and serialization
89//! let lsns = wal.append_batch(operations)?;
90//! assert_eq!(lsns.len(), 3);
91//!
92//! // For GroupCommit mode, commit and wait for durability
93//! if let Some(epoch) = wal.commit()? {
94//!     wal.group_commit_coordinator().unwrap().wait_for_flush(epoch)?;
95//! }
96//! ```
97//!
98//! **Performance Benefits:**
99//! - Single atomic LSN allocation (vs N atomic operations)
100//! - Better CPU cache locality during serialization
101//! - Reduced stripe buffer contention
102//! - **20-50% throughput improvement** for batch sizes > 10
