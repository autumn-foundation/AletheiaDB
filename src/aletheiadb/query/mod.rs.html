1//! Hybrid Query Engine for AletheiaDB
2//!
3//! This module implements the query engine that powers AletheiaDB's unified
4//! graph, vector, and temporal querying capabilities.
5//!
6//! # Architecture
7//!
8//! The query engine follows a classic database architecture pipeline:
9//!
10//! ```text
11//! ┌───────────────┐      ┌───────────────┐      ┌───────────────┐
12//! │  Query Input  │      │  Logical Plan │      │ Physical Plan │
13//! │ (Builder/AQL) ├─────►│     (Tree)    ├─────►│  (Executable) ├─────► Results
14//! └───────────────┘      └───────┬───────┘      └───────▲───────┘
15//!                                │                      │
16//!                        ┌───────▼───────┐      ┌───────┴───────┐
17//!                        │  Optimizer    │      │   Executor    │
18//!                        │ (Rules/Cost)  │      │  (Iterators)  │
19//!                        └───────────────┘      └───────────────┘
20//! ```
21//!
22//! 1. **Input**: Queries are constructed via the fluent [`QueryBuilder`] or parsed from AQL strings.
23//! 2. **Logical Plan**: A high-level tree of operations ([`LogicalPlan`]) representing *what* to do.
24//! 3. **Optimization**: The [`QueryPlanner`] applies heuristic rules and cost-based optimization.
25//! 4. **Physical Plan**: A low-level executable plan ([`PhysicalPlan`]) representing *how* to do it.
26//! 5. **Execution**: The [`QueryExecutor`] runs the plan using a pull-based iterator model.
27//!
28//! # Key Features
29//!
30//! - **Hybrid Queries**: Seamlessly mix graph traversals, vector similarity search, and filtering.
31//! - **Bi-Temporal**: All queries can be executed `AS OF` a specific valid time and transaction time.
32//! - **Vector Indexing**: Integrated HNSW index for fast approximate nearest neighbor search.
33//! - **Cost-Based Optimization**: Uses statistics to reorder operations (e.g., filter before traverse).
34//!
35//! # Examples
36//!
37//! ## 1. Hybrid Graph + Vector Query
38//!
39//! "Find documents similar to 'Rust' that are written by people Alice knows."
40//!
41//! ```rust,no_run
42//! # use aletheiadb::AletheiaDB;
43//! # use aletheiadb::core::NodeId;
44//! # fn main() -> Result<(), Box<dyn std::error::Error>> {
45//! # let db = AletheiaDB::new()?;
46//! # let alice_id = NodeId::new(1)?;
47//! # let rust_embedding = vec![0.1, 0.2, 0.3];
48//! let results = db.query()
49//!     .start(alice_id)
50//!     .traverse("KNOWS")              // Find people Alice knows
51//!     .traverse("WROTE")              // Find documents they wrote
52//!     .rank_by_similarity(&rust_embedding, 10) // Rank by content similarity
53//!     .execute(&db)?;
54//! # Ok(())
55//! # }
56//! ```
57//!
58//! ## 2. Temporal Query
59//!
60//! "What did the graph look like on Jan 1st, 2023?"
61//!
62//! ```rust,no_run
63//! # use aletheiadb::AletheiaDB;
64//! # use aletheiadb::core::NodeId;
65//! # use aletheiadb::core::temporal::Timestamp;
66//! # fn main() -> Result<(), Box<dyn std::error::Error>> {
67//! # let db = AletheiaDB::new()?;
68//! # let node_id = NodeId::new(1)?;
69//! # let time_2023 = Timestamp::new(1672531200000000, 0)?;
70//! # let tx_time = aletheiadb::core::temporal::time::now();
71//! let results = db.query()
72//!     .as_of(time_2023, tx_time)      // Set temporal context
73//!     .start(node_id)
74//!     .traverse("KNOWS")              // Traversal respects history
75//!     .execute(&db)?;
76//! # Ok(())
77//! # }
78//! ```

80//! # Submodules
81//!

84//! - [`planner`]: Logical-to-physical transformation and cost-based optimization.
85//! - [`executor`]: Iterator-based execution engine.
86//! - [`ir`]: Intermediate Representation types ([`QueryOp`], [`Predicate`]).
87//! - [`ast`]: Abstract Syntax Tree for parsed AQL queries.
