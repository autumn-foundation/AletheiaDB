1//! Query Optimization Rules
2//!
3//! Defines optimization rules that transform logical plans to more
4//! efficient forms. Rules are applied iteratively until no more
5//! transformations are possible.
6//!
7//! # Architecture
8//!
9//! Each rule implements [`OptimizationRule`] and is a stateless, zero-size
10//! struct.  The rule engine (in `planner/mod.rs`) applies rules in a fixed
11//! order, repeating until a full pass produces no changes (fixpoint).
12//!
13//! # Available Rules
14//!
15//! | Rule | Module | Purpose |
16//! |------|--------|---------|
17//! | [`PredicatePushdown`] | `predicate_pushdown` | Moves `Filter` nodes as close to data sources as possible, reducing row count early. |
18//! | [`FilterScanFusion`] | `filter_scan_fusion` | Merges `Filter(Eq)` + `NodeScan` into a single `PropertyScan`, delegating to the storage index. |
19//! | [`LimitPushdown`] | `limit_pushdown` | Propagates `Limit` through safe operators to enable early termination (top-k). |
20//! | [`OperationReordering`] | `operation_reordering` | Reorders filters and joins by cost/selectivity to minimise total work. |
21//!
22//! # Rule Ordering
23//!
24//! Rules run in the order returned by [`default_rules`]:
25//!
26//! 1. **`PredicatePushdown`** – runs first so that subsequent rules see
27//!    filters already as close to scan nodes as possible.
28//! 2. **`FilterScanFusion`** – depends on predicate pushdown having placed
29//!    `Filter` nodes directly above `Scan` nodes.
30//! 3. **`LimitPushdown`** – runs after fusion so it can push limits through
31//!    the fused `PropertyScan`.
32//! 4. **`OperationReordering`** – runs last with full cost information so it
33//!    can make globally optimal decisions about join/filter order.

50/// Trait for optimization rules.
51///
52/// Each rule attempts to transform a logical plan into a more efficient form.
53/// Rules should return `Ok(Some(new_plan))` if a transformation was applied,
54/// or `Ok(None)` if the rule doesn't apply.
55pub trait OptimizationRule: Send + Sync {
56    /// Name of this rule (for debugging/tracing)
57    fn name(&self) -> &str;
58
59    /// Attempt to apply this rule to a logical plan.
60    ///
61    /// Returns:
62    /// - `Ok(Some(plan))` if the rule was applied
63    /// - `Ok(None)` if the rule doesn't apply
64    /// - `Err(e)` if an error occurred
65    fn apply(&self, plan: &LogicalPlan, stats: &Statistics) -> Result<Option<LogicalPlan>>;
66}
67
68/// Create the default set of optimization rules.
69#[must_use]
70pub fn default_rules() -> Vec<Box<dyn OptimizationRule>> {
71    vec![
72        Box::new(PredicatePushdown),
73        Box::new(FilterScanFusion),
74        Box::new(LimitPushdown),
75        Box::new(OperationReordering),
76    ]
77}
