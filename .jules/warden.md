**2025-03-01 - Missing Validation on Parsed WAL String IDs**
**Threat:** A Denial of Service (DoS) vulnerability existed in `parse_entry_at` within `src/storage/wal/segment_reader.rs`. The code blindly constructed `InternedString::from_raw(label_id)` directly from parsed `u32` values off the Write-Ahead Log without verifying if the ID was present in the global interner. During database recovery, if a corrupted or maliciously crafted WAL segment containing unmapped string IDs was replayed, any subsequent calls to `.resolve()` on those `InternedString` instances would return `None`. If downstream logic `.unwrap()`s the `Option`, it panics, crashing the database and halting recovery entirely.
**Defense:** Added defensive boundary checks in all four paths (`CreateNode`, `CreateEdge`, `UpdateNode`, `UpdateEdge`) where a raw `label_id` is parsed. The parsed `InternedString` is now immediately checked using `GLOBAL_INTERNER.resolve_with(label, |_| ()).is_none()`. If it fails validation, a graceful `StorageError::CorruptedData` error is returned, allowing the recovery process to safely identify and isolate the corrupted segment rather than fatally panicking.
