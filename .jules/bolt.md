**[Optimized collect_structured via lazy evaluation]**
**Learning:** Collecting intermediate `Vec<T>` elements is slow, but we can avoid it. In `src/query/executor/results.rs`, `collect_structured` collected `QueryRow`s in an intermediate vector only to check if some fields like `score` and `path` are present. This meant O(n) memory allocation for the intermediate structure.
**Action:** Used `Option<Vec<T>>` for each property and initialized them on-demand when the first non-null element was found. We padded them up to `current_index` with default elements (e.g. 0.0 for scores), avoiding the double pass and saving heap allocations for all N rows!
