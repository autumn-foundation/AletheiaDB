## [Bolt Optimization] Pre-allocating query result vectors
**Learning:** Query results (`QueryResults`) were being gathered into dynamically grown vectors (`Vec::new()`) in methods like `collect_all` and `collect_structured`. However, the underlying iterators correctly implement `size_hint()`. Not utilizing this lower bound results in unnecessary reallocations as the vector grows.
**Action:** Always prefer `Vec::with_capacity(iterator.size_hint().0)` over `Vec::new()` when collecting iterators manually via `while let Some(x) = iter.next()`. If a multi-pass operation first collects a row subset and then extracts fields (like in `collect_structured`), use the first subset's `.len()` to preallocate all subsequent sub-vectors identically.
