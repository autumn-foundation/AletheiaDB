**Avoid Clone during Lexing Iterator operations**
**Learning:** `chars.clone().next()` constructs an entirely new iterator over `CharIndices` string bytes to figure out what characters follow, which includes copying a pointer and an integer. It is cheaper to use `.peek()` or peek at underlying slice directly via `.as_bytes()`. However, calling `.peek()` requires an exclusive `&mut self` borrow, so it can't be used inside methods defined with `&self`.
**Action:** Replace `lookahead = chars.clone(); lookahead.next()` with `input.as_bytes().get(pos + 1)` which uses the position tracked by `.peek()` to look at the next character directly using byte offset, avoiding building a new iterator while maintaining immutable usage semantics.
